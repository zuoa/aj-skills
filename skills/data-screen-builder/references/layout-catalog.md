# 布局目录与自定义

配置见 `assets/vue-screen/src/config/layouts.json`。预设只定义结构槽位，不定义指标、配色或引擎。统一 12 单位网格，行数由配置给出，坐标从 1 开始。角色有 metric、chart、map、list、main。

## 六套预设

| ID / 名称 | 阅读顺序 | 适用情况 | 地图与比例 |
| --- | --- | --- | --- |
| map-center 中心地图 | 顶部概览；左分析/中地图/右事件；底部辅助 | 辖区指挥、园区空间态势 | 有地图；16:9 |
| analysis-wide 主图分析 | 顶部概览；左宽主图/右辅助；底部两图 | 经营复盘、趋势叙事 | 无地图；16:9 |
| balanced-three 均衡三列 | 顶部概览；三列等宽上下两层 | 多主题总览、同级观察 | 无地图；16:9 |
| monitoring-two 双列值守 | 顶部状态；左主监测/右告警；底部两区 | 连续值守、异常优先 | 无地图；16:9 |
| comparison-four 四列对比 | 四列概览；四列等宽对比；底部汇总 | 区域、渠道、产线对照 | 无地图；16:9 或超宽 |
| panorama-wide 超宽全景 | 顶部概览；左右分析/中央宽主图 | 横向长屏、指挥室全景 | 中心 main；建议 32:9，可自定义为 map |

典型线框（不是业务内容）：

```text
中心地图                    主图分析                  双列值守
┌─────── 概览区 ────────┐   ┌────── 概览区 ──────┐  ┌────── 状态区 ──────┐
├─ 左图 ┬── 地图 ─┬ 事件┤   ├──── 主图 ───┬ 辅助┤  ├── 主监测 ──┬ 告警 ┤
├─ 左图 ┤         ├ 列表┤   │             ├ 辅助┤  │             │      │
├─ 左图 ┼── 底图 ─┤     │   ├── 辅助图 ───┴ 辅助┤  ├── 辅助区 ──┼ 事件 ┤
└───────┴─────────┴─────┘   └───────────────────┘  └─────────────┴──────┘
```

先筛掉不合适方案，再推荐 2–3 套；没有地理需求就不推荐中心地图。slot 数量只是初稿容量，不能据此增加指标；实际内容少时可合并/删除槽位，改变结构后重做框架确认。

## 自定义引导

1. 问几列、各列比例，建议二列 7:5、三列 3:6:3、四列均分。任意比例优先近似到 12 单位并说明误差；要求精确比例时扩展实现再预览。主分区列数不等于 CSS 12 个单位。
2. 问中间是否需要地图、地图的业务作用，或改用趋势、流程、视频/模型、不设中心。两列时说清地图放在哪一侧或全宽，不把“两列+中间地图”默认为三列。地图再区分二维/三维、边界/底图，不在此时生成地理内容。
3. 问顶部几块概览、侧栏各几层、是否底部通栏、告警是否常驻。
4. 确认主次、阅读顺序、留白和边框，展示线框与比例摘要，同意后写 customLayout。

示例 framework.json：

```json
{
  "version": "1", "title": "运行值守", "canvas": {"width": 1920, "height": 1080},
  "paletteId": "pine-teal", "layoutId": "custom",
  "customLayout": {
    "id": "custom", "name": "双列无地图", "description": "左监测，右事件", "aspect": "16:9", "rows": 10,
    "slots": [
      {"id": "primary", "label": "主区域", "role": "main", "layout": {"col": 1, "row": 1, "width": 7, "height": 10}},
      {"id": "events", "label": "事件区域", "role": "list", "layout": {"col": 8, "row": 1, "width": 5, "height": 10}}
    ]
  },
  "bindings": {}
}
```

手动色板用 paletteId: custom 和 customPalette，结构与色板条目一致、id 为 custom。槽位在网格内、不重叠、ID 唯一。当前实现是平面矩形排布，不支持重叠背景地图；这类需求需要扩展渲染规则并另行验收。

## 与完整页一致

空预览和完整页共用 framework.json、layout、palette。填写 bindings: {"组件ID": "槽位ID"}，每个槽位对应一个组件；组合内容先实现自定义组件，不叠入同一槽位。map 槽位绑定 map；没有地图槽位的布局不能偷偷塞入 map，main 不代替 map。

历史 designs.json 用于旧示例组合；新流程有 bindings 后不让它改变确认的颜色和结构。标题、画布尺寸同样从 framework 复用。
