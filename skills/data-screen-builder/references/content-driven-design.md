# 按内容确定风格、布局与配色

固定指标协议、组件输入、资源管理与验收方法；布局、颜色、中心内容和视觉风格由本次业务问题决定。h4、EASYV 和已生成页面只属于案例，不能变成所有项目的默认皮肤。

按 [阶段流程](workflow.md) 分别确认主题与视觉风格、色彩、布局和空框架，再详细分析指标/内容。开始阶段根据业务范围提出候选，不提前绑定完整指标体系。已有品牌或用户指定方向直接细化，允许手写主题/色彩与自定义布局；明确授权代决时记录范围。

## 布局取决于什么

- 经营分析：指标—趋势—对比构成阅读主线，主图可以是时间序列，不必放地图。
- 辖区服务/指挥：空间范围、机构点位、事件位置构成主线，地图可居中、偏左或占满背景；分析区按处置路径分配。
- 园区/设备：模型只有在空间定位、楼层或设备状态有价值时成为主视图；否则保留图表和事件列表。
- 能源/生态：时空变化、基线和异常分区决定主次，不强制青绿色或三栏。

新流程使用 `framework.json` 选择 `layouts.json` 中的结构槽位（或 customLayout），完整页通过 bindings 复用位置；旧示例仍用 `screen.components[].layout`。指标数量来自业务问题，不为对称增加指标，也不每张图重复同样注释。内容装不下时提出精简或结构调整，结构变化重新确认框架。

## 配色取决于什么

根据品牌、内容情绪、环境亮度、数据类型和状态语义构造本项目的 token。暖红/橙金可用于用户要求的辖区立体图，生态可探索青绿，经营可用浅色中性和品牌色；这些都是候选，不是行业硬编码。

分开定义表面、文本、边框、品牌强调、分类、连续/发散色阶、风险色和地图顶面/侧壁/轮廓。不同内容可以换整个搭配，同一数据实体在同一场景保持稳定颜色。品牌强调不等于异常；暖色主图仍要通过文字、形状和位置表达风险。UI、ECharts、Three.js 和 OpenLayers 共用已解析的 sRGB token。

`src/config/layouts.json` 提供六套独立结构，`palettes.json` 提供九套色板，`styles.json` 与 `visual-styles.css` 提供 [十类独立风格](style-catalog.md)，可任意组合并完整自定义。`designs.json` 仅保留历史成品样例，bindings 非空时不覆盖新框架。`theme.ts` 提供 token 类型、合并和 CSS 输出；局部表面与光照从 token 派生，不把蓝色写死在组件内部。

示例方案切换用来验证设计与数据解耦；最终项目只保留业务需要的方案，不强制给成品用户展示主题或渲染器设置。
