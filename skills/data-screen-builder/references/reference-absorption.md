# 从参考页面吸收视觉能力

当用户提供页面、截图、已有成品或说“像这个一样精致”时，在生成预览前使用本流程。先观察实际页面，再修改设计。不能根据平台名猜外观，也不能把某种装饰写成所有大屏的固定要求。

## 观察并形成可评审证据

用可用浏览器观察目标页面，记录日期、视口、主题、状态和来源。至少获取完整页面、标题、代表性面板、中心场景的截图；需要动效时观察静止与运动两种状态。支持源码或 computed style 时读取相关结构和数值；把直接读到的值、截图估计和本项目选择分开记录。网页不可访问时明确缺口，不能假称已参考。

参考的入口页可能不是用户指的大屏，先确认页面内容。保留来源 URL 和适用页面；不要将完整第三方 bundle、业务功能或数据复制进新项目。用户自己的页面可将适用组件或素材纳入其项目，但仍明确哪些是既有来源、哪些是本次改造。

本技能的 [h4 页面案例](h4-reference.md) 演示如何把一个完整成品转译成规则；它是用户本次指定的参照，不是其他任务的默认风格。

本技能已提炼 [EasyV 客户案例、DataEase V3 和 EasyV 素材广场](easyv-dataease-research.md)，形成 [十类风格](style-catalog.md)。这些是可扩展设计方向，不是用户本次确认；不得将调研中的单个案例作为所有项目默认。

## 拆成五类可复用内容

| 内容 | 提取方式 | 沉淀到哪里 |
| --- | --- | --- |
| 构图关系 | 标题/品牌/操作的基线，指标区与主体比例，侧栏与中心的面积，横竖边界 | screen layout 与布局规则 |
| token | 文字层级、数字字形、空间节奏、表面/边框/状态色、光效强度、动效时长 | `theme.ts`，UI 与图表共用 |
| 组件配方 | 标题组、指标、面板头/体/脚、图例、刻度、热力矩阵、告警行 | 独立组件及其状态示例 |
| 渲染基元 | 图标笔画、局部光轨、SVG 建筑/道路/窗格、标签锚点 | 可组合矢量组件，不用整图假装交互 |
| 验收规则 | 对齐、遮挡、裁切、阅读顺序、颜色含义、暂停/缩放行为 | 浏览器几何检查 + 截图评议 |

每类记录“参考观察 → 采用/调整/排除 → 本项目实现位置”。例如参考有五个 KPI，本项目只有三个真实问题时保留三个；采用其数字与单位对齐、轻边框及注释，不编造两个指标凑构图。

## 实现时控制细节

- 标题文字与装饰共享组件和布局约束。光线锚定文字组，两侧品牌与动作位于独立列；不使用多套绝对定位或 translateY 补丁寻找对齐。
- 每个面板有明确 head/body/foot。正文占剩余空间，图表刻度与图例预留空间，脚注和动作不能侵入图表。
- 数字、单位、标签是不同层级：数字用等宽数字特性与紧凑字形，单位缩小并按基线对齐；图表颜色、间距、字号同步使用 token。
- 场景标签、建筑和路径共享 SVG viewBox 或同一投影函数。不能让建筑在 SVG 内缩放、标签又用独立 HTML 百分比定位。
- 用主要业务控制维护阅读节奏，视觉偏好放在可展开的设置里。把调试信息留在开发环境与交付说明，不占满正式界面。
- 装饰强度按参考和受众决定。光效可以存在，但需要满足文字清晰、状态区分及可停止。

## 两类检查都要做

自动检查解决几何错误：画布进入视口，不同宽高比适配，品牌/标题/动作不重叠，面板 head/body/foot 不相互侵入，图例/刻度不裁切，场景标签跟随同一坐标。可由浏览器输出矩形快照，使用 `scripts/check_visual_geometry.py` 检查。

人工或代理视觉评议解决设计问题：同尺寸截图并排观察参考与本项目，逐项检查标题比例、空白分布、边框重量、系列线宽、数字单位、图标一致性、颜色数量和场景材质。记录实际发现及修订，不输出没有依据的“精致度 95 分”。浏览器无报错、测试通过或无滚动条不能单独证明视觉认可。

将本次选择的参考转译为可替换的 token、布局和组件配方；h4 只演示一种转译过程，不作为其他项目的默认方向。改造后交付来源分析、可复用配方、已执行几何检查和最新预览；尚未取得用户视觉认可时如实说明。
