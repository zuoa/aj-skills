# EASYV 类光效与场景设计

这是借鉴公开案例后形成的实现指导，不是 EASYV 的官方组件、专有代码或兼容格式。参考 [EASYV 智慧园区案例](https://easyv.cloud/case-detail/2.html) 的中心场景、数据覆盖层和光照层次；公开图像仅用于观察，不复制进交付项目。

## 把“酷炫”具体化

先确定主场景、构图、主光色与强度，再挑选效果。可以提出“蓝青全息指挥舱”“琥珀能源沙盘”“冷白数字孪生”等具体方向，用户有参照时提取其光线、景深、材质、构图，不只提取色号。

| 层 | 可实现的效果 | 目的与限制 |
| --- | --- | --- |
| 空间底层 | 深色雾化背景、远景光晕、透视网格、稀疏粒子 | 产生深度，不能影响文字对比 |
| 标题主视觉 | 集中式文字组、渐弱光轨、细金属线或适用的切角材质、局部辉光 | 比例与材质取自参考；光带不能穿过标题、品牌或副标题，不统一要求厚底板 |
| 主场景 | Three.js 三维辖区/模型、SVG 2.5D 示意、区域拉升、建筑材质、光柱、地面光环 | 形成视觉焦点；示意几何必须标记，装饰建筑高度不冒充实际数值 |
| 连接与引导 | 飞线、移动亮点、扫描光带、边缘流光 | 区分装饰与真实业务流向，数据不足时不把飞线解释为实时流量 |
| 数据覆盖层 | 半透明面板、切角、角标、细发光线、数字轻微辉光 | 数据保持清晰，告警色独立于品牌光色 |
| 交互层 | 选中区域光环、局部聚焦、钻取过渡 | 由真实选择触发，键盘和筛选控件可完成同样操作 |

用户要求极致展陈视觉时，读 [四类展陈强化方向](style-catalog.md#展陈强化方向允许夸张按完整视觉系统实现)，明确落实标题、边框、材质、场景和环境五层。允许大胆装饰与高强度光照，用明确主次统合它们，不把“克制”误作一律禁用装饰。首屏主焦点可以是中心场景、标题或主图；侧栏也有完整的材质与框体设计，动态流光的数量和速度需有节奏。光线明暗需有层级：主光/局部强调/环境补光，文字不使用重模糊。对照普通、低强度和高强度三种状态检查。

## 实现选择

- CSS 渐变与 transform/opacity：环境光、流光、扫描和透视网格；装饰层 `pointer-events: none`、`aria-hidden`。
- SVG：可控的光束、光环、矢量沙盘、简单建筑和区域轮廓；渐变或模糊仅作用于局部，不对全屏反复做大滤镜。
- ECharts：数据图表、真实坐标地图、数据驱动的连线和热力；颜色来自共享 token。
- Three.js/WebGL：只在用户确实需要真实三维模型、漫游、材质或复杂光照时评估，先确认模型来源、尺寸、加载预算、设备与降级方式。2.5D 示例不能称为数字孪生引擎。

模板 `TitleFrame.vue` 让标题与两侧光轨共享布局，`ScreenEffects.vue` 管环境光，`GeoView.vue` 按配置选择 Three.js/OpenLayers/SVG；`SceneMap.vue` 保留为轻量虚构建筑示意。新流程风格、配色和布局由 framework.json 选择独立 styles.json/palettes.json/layouts.json，designs.json 只供旧示例组合；图表和空间引擎共享 token。完整页组件结果、区域选择和数值来自指标查询，空框架不加载空间内容。装饰层都在同一画布内，随 `ScreenViewport.vue` 缩放，不能用独立 viewport 尺寸造成光带漂移。framework.styleId 保存新流程 UI 风格，styles.json.effects 决定是否启用装饰，ornament 选择机甲/全息/星穹/鎏金矢量系统，defaultIntensity 与 framework.effectIntensity 决定默认/明确强度，framework.visualStyle 仅兼容旧配置，screen.visuals 保存完整页强度等默认值；数据协议不保存发光参数。

## 动效控制与验收

光效暂停与数据暂停分开。`prefers-reduced-motion` 和“减少动效”关闭持续运动，但可保留静态光照；值守模式停止装饰动画、降低强度。光效强度调整 opacity/局部阴影，不改变数值、阈值颜色或聚合口径。避免快速闪烁。

验证：所有动态装饰可停止；暂停数据时指标正确标记；区域选择和重置一致；图表、文本与告警不被装饰遮挡；低性能设备可以禁用光效并保持数据可用。截图检查构图和材质，短视频或浏览器观察检查真实动画，不能仅凭静态截图宣称动效已验证。

## 强化效果的具体实现

- `FrameOrnament.vue`：ResizeObserver 取局部尺寸；轮廓、镶边、角件、金属板和流光各自成层，拐角尺寸保持稳定。每个实例的渐变 ID 唯一，卸载观察器。
- `TitleOrnament.vue`：四套 SVG 题头，基于标题所在网格定位；文字独立于矢量层，不在文字上叠模糊。
- `ScreenEffects.vue`：固定坐标粒子，云团/透视地面/光晕与全屏结构共用画布。没有独立的随机计时器或每次刷新重排粒子。
- `SceneHalo.vue`：实际空间视图之后的同心光环、投射光与标尺装饰，明确为装饰舞台，不承担地域、设备或指标语义。空框架不加载该场景层。
- `showcase-effects.css`：金属/玻璃/弧面/纹饰的差异，CSS transform、opacity、stroke-dashoffset 动画；高强度是完整默认，off 关闭动态层及辉光但保留静态形态。

实际浏览器核对 `stroke-dashoffset` 随时间变化、暂停/恢复、系统减少动效、值守、关闭光效、筛选与图表读数。截图检查结构/材质，动态入口或实录检查运动；不把静态截图称作动画验收。逐个核对角花/定位角标与 head/body/foot 的关系，不能让边框设计占用文字区。

## 从夸张到精致

已选定的四类展陈方向按 [四类精修配方](four-style-refinement.md) 分别完善。机甲保持石墨金属和机械结构，全息保持晶体折面与反应场，星穹保持光学曲面与星图，鎏金保持浮雕与金属建筑展台；饱满的指标上下文与摘要可共用，形态、材质和光源不共用一套规则。`refined-showcase.css` 与 `SpectralScene.vue` 落实这些差异，概念场景限 mock 比较入口。

用户要求饱满且精致时，参考 [琉光展厅](style-catalog.md#精致而饱满琉光展厅)：以内容层次、表面体积、低密度高光和完整主视觉实现，减少厚切角和装甲构件。先完成每个面板的读数、解释、比较或状态，再配置辅助光照。不要靠虚构同比/目标、随机数据或无意义刻度装饰提高密度。新增摘要后必须重新检查图表可用高度与文字/脚注，不能只测面板外框。

徽记、玻璃折射和概念场景均与正式数据分层；在极致展示和运行值守之间保留可控动效。正式地理资源不被 mock 场景替换，空框架始终只预览结构与材质。
