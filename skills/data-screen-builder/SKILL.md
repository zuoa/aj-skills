# Data Screen Builder

按“主题与视觉风格 → 配色 → 布局 → 自定义细化（条件分支）→ 空框架预览 → 内容分析 → 整合交付 → 检查核验”推进。先让用户看清结构，再填充内容；风格形态、布局、色彩、地图引擎和指标协议分别配置。历史案例只是参考。

## 开始与确认规则

先读 [阶段流程与交互规则](references/workflow.md)，在用户项目内复制 [确认记录模板](assets/workflow/brief.template.json) 为 `screen-brief.json`，维护当前阶段、决定、来源、确认依据、预览版本和未决项。已有项目从当前请求相关阶段开始，复用仍适用的已确认决定。

- 主题与风格、配色、布局和空框架分别确认。每轮给 2–3 个适合当前业务的候选、一个推荐及理由，同时允许用户直接输入。不要把候选菜单当作能力边界。
- 能使用交互问答工具时使用工具；否则用自然语言提问。所有选择题都允许手动回答。文件上传/路径通过正常对话收集，不让仅支持文本的问答工具承担上传。
- 用户已明确指定的决定即视为该项确认，不重复提问。用户明确说“这些你来定/跳过确认”时记录授权范围并继续；“帮我制作”本身不代表跳过上述确认。
- 待确认时可以准备候选、资源和可评审产物，等待后再做依赖该决定的工作。不能把推荐、超时、未回复或代理自检记成用户认可。普通实施授权不自动取消此技能的交互阶段。
- 上游变更只回退受影响部分。主题改变需重审内容与视觉；配色改变保留指标和结构；布局改变重做框架及槽位映射。不要每次修改都重跑访谈。

## 1. 分析并确认主题

明确业务主题、受众、看屏目的、展示/值守模式、观看条件和目标分辨率；只需知道大致内容范围，不在此时展开完整指标体系。主题包含“讲什么”和“呈现什么气质”，配色另行确认。

给出如“经营复盘 / 运行值守 / 空间指挥”等与需求相关的主题建议，并说明其阅读主线。允许用户手写主题、沿用品牌或提供参考。以 1920×1080 作为暂定预览尺寸时明确它尚未验证实体墙屏观看效果。把选定主题和必备/排除项写入记录。

读 [视觉风格目录](references/style-catalog.md)，在本阶段按业务给 2–3 个有实质差异的方向/小样，记录 `stages.visualStyle`。候选至少在标题、面板、数字、主视觉、图表、动效中的三个维度有差异；不能只换颜色或用“高级科技风”概括。内置 [styles.json](assets/vue-screen/src/config/styles.json) 十五套 UI 规则与九套色板、六套布局独立搭配，也可扩展 CSS/组件。选择实景、地球、工业模型或文化主视觉时明确资产条件，风格选择本身不会生成这些资产。用户要求精致/饱满/少机甲时，优先琉光展厅，从指标层次、图表摘要、材质和完整场景提升表现；不得靠虚构增长率、目标或无关卡片填满。用户要求夸张/极致视觉时，推荐四类展陈强化方向，落实异形轮廓、多层材质、光源与动效，默认高强度；不自行收敛为细线框。已指定/授权的决定直接沿用，不额外增加等待阶段。

参考页面或截图按 [参考吸收](references/reference-absorption.md) 实际观察；h4 仅是 [示例案例](references/h4-reference.md)，不作为默认主题。

用户点名机甲、全息、星穹、鎏金要求精修时，读 [四类精修配方](references/four-style-refinement.md)，沿各自材质、题头、边框、徽记与主视觉改进。内容层次可共用，外观不能统一改成曲面玻璃；交付同配色对照和各自推荐配色预览。

## 2. 确认色彩设计

按主题、品牌和环境推荐配色，展示色板及背景/文字/强调/分类/状态色的用途。内置色板见 [palettes.json](assets/vue-screen/src/config/palettes.json)，可任意搭配布局。

允许用户给 HEX、品牌规范、参考图或自然语言描述，再转换为完整 token；先补全缺失色并提出可读性修正，获得确认。不要把行业固定成某种颜色，或让换配色自动改变布局/地图引擎。具体规则见 [设计决策](references/design-decisions.md)。

## 3. 选择并确认布局

从 [布局目录](references/layout-catalog.md) 选 2–3 套推荐，提供小线框、阅读顺序、是否含地图、适合比例和取舍；始终提供“自定义”。实际配置见 [layouts.json](assets/vue-screen/src/config/layouts.json)，六套布局为中心地图、主图分析、均衡三列、双列值守、四列对比和超宽全景。

布局只定义容器、面积和阅读层级，不借此编造 KPI 或业务内容。无需地图时推荐无地图方案；地图、三维模型、趋势主图和流程主图不能混为一谈。

## 4. 自定义布局（仅选择自定义时）

按 [自定义引导](references/layout-catalog.md#自定义引导) 分轮明确：几列与宽度比例 → 中间是否需要地图/主图及其面积 → 顶部概览、侧栏、底栏与模块数量 → 阅读顺序和间距。允许 ASCII 草图、截图、百分比或直接描述。

把人的“2/3/4 列”转换成底层 12 单位网格中的分区，二者不是同一概念。写入 `framework.json.customLayout`，检查范围、正整数、重叠与空间角色；不支持的特殊叠层需明确扩展渲染规则，不能假装已有配置支持。

## 5. 生成空框架预览并确认

使用已选主题、风格、配色、画布和布局生成真实可运行页面，只展示标题、框线、留白、槽位编号及“地图区域/主图区”等结构标签。**不展示业务数值、指标标题、图表曲线、地图地理细节、排名、示例数据或业务文案**；不请求指标 API、地图资源，不创建图表/WebGL。空框架不是加载骨架或填了 mock 的成品。

新项目复制模板到用户项目，不在 skill 目录生成业务产物：

```bash
python3 <skill-path>/scripts/create_screen.py <new-project-directory> --style editorial-light --layout analysis-wide --palette mist-indigo --title "经营分析"
cd <new-project-directory>
npm ci
npm run validate:framework
npm run dev:framework
```

`/?view=framework` 独立加载框架页，不依赖 `metrics.json`。页面支持风格/布局/色板独立比较和导出候选配置；同色同布局比较形态差异；切换或导出不等于确认，导出文件需由代理核对后写回 `src/config/framework.json`，包括 `styleId` 和可选 `effectIntensity`。自定义配置由交互引导后填写，预览页不承担拖拽编辑器。

给出预览入口、截图、版本和确认重点（比例、主次、地图位置、风格、配色、留白）。用户确认当前版本后再进入内容分析；要求修改则更新预览再确认。明确授权代决时按授权继续，但记录 delegated，不能记录成用户看过页面。浏览器不可用时交付可运行入口并标记视觉检查未执行。

## 6. 分析指标体系或内容

先确认内容路径：本地文件、检索生成或两者结合。按 [内容与来源](references/content-sourcing.md) 读取表格/报告/API 文档，或检索权威公开资料，构造“业务问题 → 指标/非指标内容 → 口径与来源 → 表现形式 → 框架槽位”的映射。

区分真实数据、公开引用、推导值、演示数据和待补内容。检索可生成建议指标体系，不能据此虚构企业经营值。缺失口径、单位、时间范围、来源或访问权限明确保留缺口；未知数不填 0。输出内容清单供校对；关键口径冲突和结构变更需确认，已授权范围内的例行填充直接推进。

如果真实内容装不下已确认框架，给出精简、次级详情/分页或调整布局的建议；需要改变结构则回到阶段 3–5，不强行压缩、不悄悄换布局、不为填满容器增加指标。

## 7. 整合内容并交付

默认 Vue 3 + TypeScript + Vite + ECharts；已有工程复用其栈和协议，未经要求不迁移。读 [指标契约](references/metric-contract.md) 和 [接入指南](references/integration.md)。机器权威为 [JSON Schema](assets/vue-screen/src/contracts/contract.schema.json)。

在 `framework.json.bindings` 登记“组件 ID → 槽位 ID”；完整页直接复用同一风格、布局和色板，校验每个组件和槽位的一对一关系及地图角色，不按标题猜绑定。该映射非空时完整页进入框架配置模式，历史 `designs.json` 组合不覆盖它。

展示组件消费统一契约，不直接调用业务 API 或聚合业务指标。mock 和 HTTP 使用同一结果；真实接口失败不切回模拟值。筛选/钻取使用共享查询上下文，标明过期、暂停、空和失败状态。密钥留在现有后端，不放进 `VITE_*` 或静态资源。

**每个生成的大屏都必须保留隐藏的指标填报入口**，常规大屏及显示设置不显示入口按钮。模板通过 `Ctrl/⌘ + Shift + E` 或 `?view=report` 打开填写界面；沿用现有栈时实现等效能力。数字、分组、趋势、表格及地图数据均走同一查询层，填报保存到当前浏览器 `localStorage` 后立即更新，刷新后保留，定时请求不能覆盖。按大屏与查询范围隔离，提供恢复原始数据、类型校验、未知/零/空记录区分和明确的本地填报来源。空框架阶段不加载填报和业务数据。交付时附 [填报说明](assets/vue-screen/REPORTING.md)，说明隐藏入口、缓存范围及仅当前浏览器有效；具体接入见 [接入指南](references/integration.md#隐藏指标填报)。

按需读 [空间渲染](references/spatial-rendering.md) 和 [光效设计](references/cinematic-effects.md)，支持 Three.js、OpenLayers、SVG 边界及自定义/高德 GeoJSON。保持稳定 ID、坐标声明和资源卸载。虚构边界、简单拉升不能称为实际辖区或完整数字孪生。

交付源代码、可运行入口、框架配置/截图、完整页截图、确认记录、内容来源与指标/API 映射、运行说明及验收记录。此时为交付候选，完成阶段 8 后才给最终结论。实际 API 缺失时可交付演示或适配入口，明确真实接入未验证；不自动发布生产。

## 8. 检查核验并修正

读 [运行与验收](references/runtime-and-acceptance.md)，按 [验收清单模板](assets/workflow/acceptance.template.md) 对照已确认需求逐项记录证据与结果。发现问题先修复，再重测受影响项；不能只给问题清单就算交付结束。

```bash
npm run validate:framework
npm run validate
npm test
npm run build:demo
python3 <skill-path>/scripts/validate_screen.py <project-directory>
```

检查三个层次：需求一致性（主题/风格/配色/结构与确认版本）→ 内容正确性（数值/单位/时间/来源/口径及 mock 标记）→ 页面与运行（目标尺寸、内部对齐裁切、图例、联动、异常、资源释放）。生产构建使用 HTTP provider，并另行核对真实 API。

桌面使用画布宽高等比缩放、居中留边；窄屏重排。用实际浏览器检查整体与面板内部，几何数据可交给 `scripts/check_visual_geometry.py`。参考和产物同尺寸查看；无滚动条或自动通过不代表视觉认可。无法执行的检查记 `not-run`；最终明确已验证范围、未决项和用户认可状态。

## 资源边界

辅助设计可按需使用已安装的 frontend-design 等技能，不构成安装硬依赖。首版不自动建设拖拽编辑器、BI 指标计算平台或数据库连接器大全。更多原理与外部依据见 [来源](references/sources.md)，只按需加载。
