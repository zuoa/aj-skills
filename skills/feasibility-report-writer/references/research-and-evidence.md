# 联网调研与信源规范（Stage 2 / Stage 4）

可研报告的「政策依据」「国内外现状」「产业数据」「效益测算」必须有信源支撑。本规范管两件事：怎么调研、怎么把信源做成可人工复核的清单。

## 1. 调研纪律

**有网络能力时必须实际执行外部检索**，不得只凭模型记忆给结论。检索上限 4–5 次，按目的分类：

| 次序 | 目的 | 用于章节 | 核查重点 |
|---|---|---|---|
| 1 | 政策依据（国家/省/市文件） | 第一章 | 文号、发布机构、发布日期、原文条款 |
| 2 | 国内外研究现状（近 3–5 年） | 第二章 | 团队/机构、成果、时间、期刊/报告出处 |
| 3 | 技术标杆/同类项目 | 第一、四章 | 技术路线、指标、差距 |
| 4 | 产业/市场数据 | 第一、六章 | 统计口径、发布机构、年份 |
| 5（备） | 效益测算基线 | 第六章 | 测算依据、基线值 |

**红线**：绝不编造文号、数据、作者、机构或链接。检索未命中或无法核验时，如实标注；只凭摘要/二手报道的，标 `基于摘要或二手`。

**无网络能力时**：在调研底稿与信源清单**显式写「未执行外部检索」**，仅列用户提供材料来源与建议检索策略（检索式、目标数据库），不输出虚假高相关结果。

## 2. 必做三项判断（调研结论）

1. **技术可行性与创新性初判**：核心技术成熟度、创新点是否成立、与标杆的差距；
2. **主要风险（3–5 条）**：技术风险、数据/场景风险、合规风险、推广风险；
3. **推进建议**：是否值得立项、关键前提、建议优先级。

以「关键发现」表呈现：发现 | 数据/证据 | 来源（信源清单序号） | 时间戳。

## 3. 信源清单（独立交付物，人工复核用）

**两条记录、双向一致**（均在工作目录的 `outputs/` 下）：
- `outputs/research/sources.json` —— 机读，逐字段结构化；
- `outputs/参考文献与信源清单.md` —— 人读，表格化，Stage 4 由 `{baseDir}/scripts/generate_docx.py --sources` 生成。

### sources.json 字段

```json
[
  {
    "id": 1,
    "type": "政策文件",            // 政策文件/期刊论文/行业报告/统计数据/新闻报道/项目案例/用户提供材料
    "title": "《……》",
    "issuer": "发布机构",
    "date": "2024-01",            // 发布日期；访问日期另列 accessed
    "accessed": "2026-08-06",
    "url": "https://……",
    "used_in": "第一章·背景",       // 用于报告哪章·引用了什么
    "claim": "引用的具体数据/结论",
    "status": "已核验原文"          // 已核验原文/基于摘要或二手/仅检索命中未核验/未执行外部检索
  }
]
```

### 参考文献与信源清单.md 表格

| 序号 | 类型 | 标题 | 发布机构 | 日期(发布/访问) | 链接 | 引用要点（报告章节·引用内容） | 核验状态 |
|---|---|---|---|---|---|---|---|

## 4. 正文↔信源对应（引用门）

**正文不出现任何 `[信源N]` 标记**；政策文号、产业数据、现状结论、标杆案例等外部引用，统一以独立信源清单承载，靠每条的「引用要点（报告章节·引用内容）」与正文对应。Stage 4「引用门」校验（见 `quality-checklist.md`，由 `{baseDir}/scripts/generate_docx.py` 的 `citation_audit` 辅助）：

- 正文无 `[信源N]` 残留（脚本导出时会自动剥离，但源稿也应干净）；
- 信源清单每条都有标题、链接，且标注「用于哪章·引用了什么」（无空 `used_in`）；
- 链接可达性抽查，失效链接标红并提示人工复核；
- `sources.json` 与 `参考文献与信源清单.md` 条目与序号一致。

人工复核流程：按信源清单**逐条** → 其「引用要点」指向的报告章节与引用内容 → 回正文核对该数据/结论 → 点链接对照原文是否确实支撑。

## 5. 调研底稿格式（`outputs/research/research_dossier.md`）

```markdown
# 调研底稿

检索状态：[已执行外部检索 N 次 / 未执行外部检索]
检索时间：[范围]

## 关键发现
| 发现 | 数据/证据 | 来源 | 时间戳 |
|---|---|---|---|

## 三项判断
1. 技术可行性与创新性初判：……
2. 主要风险：……
3. 推进建议：……

## 建议补充检索（未命中或无网时）
- 检索式 / 目标数据库 / 目的
```
