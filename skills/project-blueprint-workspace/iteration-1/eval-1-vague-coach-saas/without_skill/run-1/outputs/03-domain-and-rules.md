# 领域模型、权限与候选规则

## 1. 核心对象

| 对象 | 作用 | 最少信息（草案） | 备注 |
|---|---|---|---|
| 教练账号 | 登录与数据归属 | 身份标识、登录凭据关联、账号状态 | 登录方式待定 |
| 教练资料 | 公开预约页展示 | 展示名、简介或说明、联系方式展示策略 | 哪些字段公开需确认 |
| 课程 | 描述可预约服务 | 名称、状态、时长或结束时间规则、说明 | 价格、地点、容量均待定 |
| 可用时段 | 表达可被预约的时间 | 教练、课程或适用范围、开始、结束、状态 | 单次/重复规则待定 |
| 学员 | 预约所需身份信息 | 姓名或称呼、至少一种联系方式 | 是否创建账号待定 |
| 预约 | 连接课程、时段、教练与学员 | 唯一标识、开始/结束、状态、创建来源与时间 | 应保存预约时的关键快照 |
| 通知记录 | 追踪关键消息 | 预约、渠道、类型、状态、时间 | 渠道待定 |
| 操作记录 | 追踪关键变更 | 对象、动作、操作者、时间、必要上下文 | 不等于全量日志平台 |

## 2. 关系草图

```text
教练账号 1 ── 1 教练资料
    │
    ├── * 课程
    ├── * 可用时段
    └── * 预约 * ── 1 学员
                    │
预约 1 ── * 通知记录
预约/课程/时段 ── * 操作记录
```

“学员”是否需要长期独立实体取决于复购识别、账号和隐私策略。如果首版只需一次性预约，也可先把必要联系信息安全地保存在预约中，同时避免未经证据建立复杂学员 CRM。

## 3. 候选业务规则（均需确认）

### 可预约性

- 只有已发布课程、有效链接和未来的开放时段可被预约。
- 同一教练在重叠时间内默认不能接受两个预约；团课或多容量场景确认后另建规则。
- 预约提交必须在服务端重新检查，不依赖客户端之前看到的结果。
- 课程时长与时段长度如何对应尚未决定。
- 预约提前量、最远可预约日期、时段间缓冲均不能擅自填写数字。

### 预约确认

- “立即确认”或“教练审核”尚未确定，两者会改变状态机和通知文案。
- 一个客户端请求因重试被多次发送时，应避免生成重复预约。
- 预约记录应保留当时的课程名称、时间等必要快照，避免课程修改改变历史含义。

### 取消与改期

- 取消截止时间、是否需要原因、能否恢复尚未确定。
- 取消后的时段是否重新开放尚未确定。
- 改期可通过“保留原预约变更轨迹并建立新时间关联”实现；具体交互待定。

### 数据与隐私

- 只收集完成预约和通知所需的信息。
- 教练只能访问属于自己的课程、时段、预约和必要学员信息。
- 公开页面不得暴露其他学员、内部标识或后台信息。
- 数据保留期、导出、更正与删除流程需根据目标市场的要求确认。
- 日志和分析事件不应包含不必要的联系方式或自由文本。

## 4. 权限矩阵草案

| 动作 | 教练 | 学员/公开访客 | 平台支持 |
|---|---:|---:|---:|
| 管理本人课程与时段 | 是 | 否 | 默认否 |
| 查看本人名下预约 | 是 | 否 | 仅经授权的必要支持 |
| 查看公开课程与可约时段 | 是 | 是 | 是 |
| 创建预约 | 可代约与否待定 | 是 | 默认否 |
| 查看单个预约详情 | 是 | 通过安全凭据，仅本人预约 | 仅经授权 |
| 取消/改期 | 按规则 | 按规则及安全验证 | 仅必要支持 |
| 查看其他教练数据 | 否 | 否 | 不应默认拥有 |

平台支持权限是否需要在 MVP 中落地，取决于运营模式；无论如何都不应通过共享教练账号处理支持问题。

## 5. 一致性与时间模型

- 预约开始与结束时间应以明确时区语义保存并展示。
- 服务端是可预约状态的最终判断者。
- 对会影响预约的并发写入使用数据库唯一约束或等价的原子保护；具体实现随技术选型确定。
- 已有预约与排期编辑冲突时，必须显式阻止或进入人工处理，不静默覆盖。
- 删除业务记录优先采用可审计的停用/取消语义；真正删除遵循隐私和保留策略。

## 6. 技术边界（有意保持简单）

现阶段只确定逻辑边界，不指定框架、云厂商或数据库品牌：

```text
教练网页管理端 ─┐
                 ├─ 应用服务/API ─ 数据存储
学员手机网页 ────┘        │
                          └─ 通知服务（渠道待定）
```

建议首版采用一个可部署的应用和一个主数据存储即可。只有在真实负载、团队能力、合规或集成要求出现后，再评估服务拆分、消息队列、搜索系统等复杂组件。

## 7. 非功能要求清单（目标值待定义）

- 安全：可靠认证、授权校验、输入验证、传输保护、秘密管理。
- 可用性：预约成功结果可恢复；关键失败有可观察记录。
- 性能：移动网络下核心页面可接受；具体指标需基线测试后确定。
- 兼容性：目标手机浏览器范围待确认。
- 可访问性：表单标签、键盘操作、焦点、对比度、状态文本满足选定标准。
- 备份恢复：恢复目标、频率和演练方式待部署环境确定。
- 审计：对课程发布、排期、预约状态等关键动作保留必要轨迹。
