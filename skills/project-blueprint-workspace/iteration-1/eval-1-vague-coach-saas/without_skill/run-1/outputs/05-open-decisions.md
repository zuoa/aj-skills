## 4. 临时设计原则（不是业务答案）

在上述事项未定时，可使用以下原则继续低成本原型，而不固化实现：

- 原型优先演示一对一预约，但明确标注这只是验证起点。
- 将付款、团课容量、套餐和多教练组织留在范围外。
- 学员端表单使用占位字段，并在测试中询问哪些信息真正必要。
- 立即确认与人工确认分别画出关键状态，不提前删除任一路径。
- 所有涉及时间的界面展示时区占位说明，不假设用户所在地。
- 不为未确认需求预建微服务、复杂权限系统或大量第三方集成。
