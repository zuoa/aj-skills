# 用户流程与体验蓝图

## 1. 教练首次设置

### 主路径

1. 教练创建账号并登录。
2. 填写预约页必须展示的信息。
3. 创建一个课程，填写名称及预约所需的必要属性。
4. 设置可预约时间。
5. 预览学员手机页面。
6. 发布并复制预约链接。

### 完成条件

- 学员链接可访问。
- 页面只展示已经发布且实际可约的内容。
- 教练可以辨认当前是否处于“未发布、已发布、已停用”等状态。

### 异常与空状态

- 没有课程：引导先创建课程，不展示失效的预约入口。
- 有课程但没有时段：公开页明确显示暂无可约时间。
- 资料不完整：指出阻塞发布的具体字段。
- 链接已停用：学员看到友好说明，不能继续提交。

## 2. 教练维护可用时间

### 主路径

1. 选择课程或适用范围。
2. 新增、编辑或删除可用时间。
3. 系统提示与现有预约、不可用时间或其他课程的冲突。
4. 教练确认变更。
5. 公开页同步反映仍可预约的时间。

### 必须设计的冲突处理

- 删除或缩短已有预约覆盖的时段时，不应静默使预约失效。
- 两个课程是否可使用同一时段，取决于“教练本人”是否是唯一资源；当前倾向视为冲突，仍需确认。
- 临界时间、跨日与时区必须有一致解释。

## 3. 学员完成预约

### 主路径

1. 学员打开教练分享的链接。
2. 查看教练、课程与预约须知。
3. 选择课程（若链接未直接指向某课程）。
4. 选择日期和可用时段。
5. 填写最少必要信息，并确认已知规则。
6. 提交预约。
7. 系统原子地再次验证时段并创建预约。
8. 页面展示预约结果和后续操作入口。
9. 系统按确定的渠道发送通知或凭据。

### 移动端体验要求

- 主要操作无需横向滚动或精确点击。
- 时段使用明确日期、星期和时间表达。
- 表单错误紧邻字段展示，并保留已填写内容。
- 提交时防止重复点击产生重复预约。
- 不以颜色作为状态的唯一提示。

### 竞争预约

若两位学员几乎同时选择同一时段：

1. 服务端以最终提交为准执行唯一性检查。
2. 仅一个预约可以成功。
3. 失败方得到“该时段刚被预约”的明确提示，并返回可选时段。
4. 不显示技术错误，也不伪装为预约成功。

## 4. 教练查看与处理预约

### 主路径

1. 教练登录并打开预约列表。
2. 按日期或状态查看即将到来的预约。
3. 打开预约详情，查看完成服务所必需的信息。
4. 执行允许的操作，例如取消；改期规则待定。
5. 系统记录变更，并按规则通知学员。

### 列表最少应表达

- 课程与预约时间。
- 学员识别信息（仅展示必要字段）。
- 当前预约状态。
- 是否有待处理的异常。

## 5. 取消与改期

这一流程高度依赖业务规则，当前只定义安全框架：

- 发起方必须能被识别或通过安全链接验证。
- 系统在操作前展示影响，并在操作后给出新状态。
- 取消后是否立即释放时段必须有明确规则。
- 改期应被建模为可追溯操作，不能覆盖掉原始预约记录。
- 若涉及付款或退款，应在支付范围确认后单独设计，不能先假设自动退款。

## 6. 建议的预约状态草案

状态名称需结合是否付款、是否需要教练审核后再精简。

```text
待确认（仅在需要人工确认时存在）
   └──→ 已确认 ──→ 已完成
          ├──→ 已取消（教练）
          ├──→ 已取消（学员）
          └──→ 未到场（若业务需要）
```

若采用“可用即确认”的模式，则首版可不设“待确认”。状态变化应保存发生时间、操作者和原因（原因是否必填待定）。

## 7. 服务恢复与边界场景

- 提交后网络中断：学员再次打开结果入口时，应能判断是否已成功，不重复建单。
- 通知发送失败：不撤销已经成功的预约，系统保留可重试或人工处理的迹象。
- 教练停用课程：已有预约如何处理必须提示教练并保留记录。
- 学员填写错误联系方式：教练如何纠正、谁可以编辑需确认。
- 时区不同：公开页应明确展示采用哪个时区；首发是否只支持单时区待定。
- 过期页面或链接：不给出敏感细节，提供重新访问预约主页的路径。
