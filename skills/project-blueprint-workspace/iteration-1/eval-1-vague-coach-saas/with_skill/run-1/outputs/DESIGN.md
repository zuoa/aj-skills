# 产品设计约束草案

## 体验原则

| 原则 | 用户结果 | 反模式 | State |
|---|---|---|---|
| 时间选择先于信息填写 | 学员先确认有合适时段，再投入填写成本 | 先要求注册或填写长表单才展示时间 | provisional |
| 预约结果无歧义 | 学员清楚知道预约成功、失败或需要重试 | 超时后只显示旋转动画或模糊“已提交” | provisional |
| 教练按任务而非配置导航 | 发布时段和查看预约可直接到达 | 首屏堆放暂未需要的 CRM/营销模块 | provisional |
| 手机端优先完成预约 | 单手触控、窄屏和软键盘下可完成核心任务 | 直接压缩桌面管理表格 | confirmed（平台）；具体表现 provisional |

## 学员完成预约

暂定流程序列：打开教练链接 → 查看可用日期/时段 → 选择 → 填写最终确认的必要信息 → 核对 → 提交 → 明确结果。不得在结果未确认时自动回到首页。取消、改期、支付和通知入口由 TBD-BOOK-002、TBD-NOTIFY-001 决定。

## 教练维护可预约时间

管理端需要同时表达“已发布、尚未发布、已被预约、不可操作”这些不同含义；具体排班形式（一条条时段、规则生成或课程场次）由 TBD-BOOK-001 决定，当前不画死交互。

## 教练查看预约

预约列表默认要能识别日期/时间、预约人和状态，但最终字段及排序均待业务规则确认。空列表、读取失败和无权访问必须视觉与文案上可区分。

## 权限与会话状态

教练会话过期时保留当前页面上下文并要求重新认证；认证后是否恢复未提交编辑取决于最终会话方案。跨工作区访问只呈现安全拒绝，不暴露其他教练数据。

## 视觉方向

- **Direction**：pending；用户没有提供品牌、参考产品或“克制/表达、紧凑/宽松”等方向偏好，见 TBD-DESIGN-001。
- **暂定信息层级**：预约页以教练/课程识别、可约时间和主操作为核心；管理端以日期与状态扫描为核心。
- **明确避免**：仅凭“现代、简洁、高级”自行制造品牌；用颜色作为唯一状态信号；在预约页加入无需求依据的营销组件。
- **字体、色彩、间距、圆角、阴影、动效、图像**：均等待视觉方向；这里只要求语义 token，不预填具体数值或品牌色。

## 设计 token 与组件

| 主题 | 来源/决定 | Override policy | State |
|---|---|---|---|
| 色彩 | 使用语义角色（背景、文本、主操作、成功、警告、错误、焦点），具体值待品牌与对比验证 | 业务组件不得写无语义颜色 | provisional |
| 字体层级 | 页面标题、区块标题、正文、辅助信息、表单标签/错误；具体字族字号待定 | 不为单页增加孤立层级 | provisional |
| 间距/尺寸 | 使用共享 token；具体比例和触控尺寸在可用性验证时确认 | 核心触控操作必须适合手机输入 | provisional |
| 组件来源 | 现有设计系统不存在；自建还是采用轻量组件库取决于技术栈 | 选择前不创建平行组件体系 | pending，TBD-DESIGN-001 |

## 无障碍与内容

- **Accessibility target**：暂定 WCAG 2.2 AA；若目标市场/合同有其他要求需重评。
- **键盘/焦点/触控**：所有操作可键盘到达；焦点可见且顺序符合任务；触控区域与间距需经移动端检查。
- **对比与非颜色提示**：状态同时使用文本/图形或结构，不只依赖颜色；最终 token 必须通过对比验证。
- **屏幕阅读器/语义**：日期选择、表单错误、加载和结果变化有可理解名称与公告；标题层级和标签关联正确。
- **本地化与文本扩展**：语言、日期格式、时区、姓名/电话格式和 RTL 适用性待 TBD-MARKET-001；布局不可依赖固定文案长度。
- **内容语气**：动作明确、不过度承诺；错误说明“发生什么、预约是否成立、下一步是什么”。术语以 SPEC 为准。
