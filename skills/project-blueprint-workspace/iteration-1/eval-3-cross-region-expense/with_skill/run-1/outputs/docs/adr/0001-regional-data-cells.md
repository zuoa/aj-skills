# ADR 0001: 按租户 home region 划分区域数据单元

- Status: proposed
- Date: 2026-09-10
- Decision owner: TBD-ARCH-001
- Related requirements: PRD-REGION-001, SPEC-REGION-001

## 背景与决策驱动

平台服务中国、欧盟和美国客户，处理身份、发票、银行账户与支付数据；用户明确要求欧盟数据留在欧盟，且生产 RPO 为 15 分钟、RTO 为 2 小时。该约束要求数据存储、备份、日志、异步消息和灾难恢复都具备区域边界。

## 候选

| Option | Benefits | Costs/risks | Constraint fit |
|---|---|---|---|
| 单一全球数据面 | 运维最简单、统一查询方便 | 难以证明欧盟数据不在欧盟外，故障转移可能越界 | 不满足已知硬约束 |
| 区域数据单元+最小全球路由控制面 | 明确驻留与故障域，共享一套产品逻辑 | 多区域部署、迁移和运营更复杂 | 最符合硬约束 |
| 每租户独立部署 | 隔离最强、可按合同定制 | 成本、升级和观测复杂度高 | MVP 缺乏必要证据 |

## 决定

暂定选择区域数据单元：CN、EU、US 各自拥有应用、关系库、对象存储、异步任务与审计存储；租户绑定唯一 home region。全球控制面只保留路由所需的非敏感伪名元数据。EU 的高可用和灾备只使用欧盟内位置。

该决定仍需法务确认“欧盟数据”及跨境访问定义，并由安全负责人确认控制面、遥测和支持流程不会泄漏受约束数据。

## 后果

- Positive: 区域边界可测试；故障不会隐式跨区；供应商可按区域替换。
- Negative: 至少三套生产数据面；发布、迁移、对账和支持流程需要区域化。
- Follow-up: 建立数据资产与处理者矩阵、区域 IaC 策略、EU 内恢复演练和跨区遥测脱敏测试。

## 重评或替代条件

当法务定义否定最小全球元数据、客户要求租户专属实例、某区域不可获得满足 RPO/RTO 的服务，或经验证的容量/成本模型证明当前单元不可行时重评。
