# 跨区域 B2B 费用管理平台：可评审蓝图草案

状态：Draft v0.1（2026-09-10）  
范围：中国、欧盟、美国；Web 与移动端；B2B 多租户 SaaS。

> 本文档集是产品与技术设计草案，不构成法律意见、安全认证或合规结论。所有标为 **[LEGAL]**、**[SECURITY]** 的事项必须由相应负责人确认后才能作为发布依据。

## 1. 目标与成功条件

- 员工上传发票、创建费用单并查看状态。
- 经理按策略审批、退回或拒绝。
- 企业管理员配置组织、预算、审批流、角色和 SSO。
- 通过抽象层接入区域适用的第三方支付服务；平台不直接持有资金。
- 以区域数据平面实现租户与数据驻留隔离；欧盟客户数据默认且持续留在欧盟。
- 生产环境达到 RPO ≤ 15 分钟、RTO ≤ 2 小时，并以演练结果而非配置声明验收。

## 2. 非目标（首版）

- 自建银行卡收单、清算网络或资金托管。
- 跨租户共享发票、预算或身份数据。
- 对税务有效性作自动法律判定；OCR/规则只提供辅助结果。
- 宣称获得任何认证或满足所有地区法律要求。

## 3. 关键设计结论

1. 采用“中国 / 欧盟 / 美国”三个隔离的区域数据平面，每个租户创建时绑定 `home_region`，默认不可在线迁移。
2. 全球入口仅保存不含个人信息的租户路由标识；业务数据、身份映射、发票、银行账户令牌、日志和备份留在租户所属区域。
3. 应用服务无状态化，核心业务数据库按区域高可用部署；对象存储保存发票原件并启用版本、加密与恶意文件隔离。
4. SSO 采用企业级 OIDC/SAML 联邦；授权仍由平台区域内 RBAC/ABAC 决定。
5. 支付采用 provider adapter + webhook inbox/outbox；只保存支付方令牌和必要的掩码字段，不保存完整银行账号（除非经专项评审批准）。
6. 每个区域采用多可用区运行，另设同法域灾备位置；欧盟灾备、备份与运维导出均不得离开欧盟边界。

## 5. 共同假设

- “欧盟客户”按合同指定的数据驻留区域判定，而非仅按用户当前 IP；租户签约时锁定区域。
- 中国区使用可在中国大陆合法运营的云与供应商；域名、备案和密码/跨境要求尚待确认。
- 支付供应商负责受监管的支付能力；平台仍负责安全集成、权限、审计和供应商风险管理。
- 移动端不离线永久保存发票与银行信息；临时文件加密并在上传完成或超时后清理。
