# AI 客服协作平台 PRD

## 问题、用户与目标

- 目标用户：通过 Web 控制台接待访客的企业客服坐席、班组长和知识库管理员。
- 核心任务：坐席接收对话，查看基于企业知识库生成的草稿，编辑或确认后发送。
- 产品目标：缩短人工组织回复的时间，同时保持最终发送权在人类坐席手中。
- 成功指标：AI 草稿采纳率、坐席首响时长、人工接管成功率、P95 首 token 延迟和单会话成本；业务目标值在试点前由产品负责人设定。

## MVP 与非目标

### MVP

- 访客聊天接入、会话分配、坐席 Web 工作台、消息历史与基本权限。
- 企业知识库摄取、检索增强的流式回复草稿、引用来源展示。
- 所有 AI 草稿必须由坐席显式确认；模型不可用时继续纯人工聊天。
- 运行审计、基础监控、成本护栏和多租户隔离。

### 非目标

- AI 自动向访客发送消息、语音/视频客服、移动 App、工单/CRM 全量替代。
- MVP 不承诺多模型自动路由、微服务、Kubernetes 或自建基础模型。

## 核心旅程

| 旅程 | 角色 | 触发 | 成功结果 | 异常结果 |
|---|---|---|---|---|
| 接待访客 | 坐席 | 新访客消息到达 | 会话进入工作台并可双向聊天 | 实时链路恢复后补齐持久化消息 |
| AI 协作 | 坐席 | 请求生成草稿 | 草稿逐 token 显示并带知识引用 | 超时/故障时提示并允许人工回复 |
| 人工确认发送 | 坐席 | 编辑并点击发送 | 仅确认后的最终文本送达访客 | 未确认草稿绝不外发 |
| 知识更新 | 管理员 | 上传/更新企业资料 | 新版本可检索且可追踪 | 失败任务可重试且不污染已发布索引 |

## 产品需求

### PRD-CHAT-001 — 实时人工聊天

- 用户价值：坐席可在 Web 控制台连续接待访客。
- 要求：系统支持普通聊天峰值 3000 个并发连接，并保存会话和消息状态。
- 产品验收：压测达到连接目标；断线重连后不重复、不越租户地恢复消息。
- State: confirmed；Source: 用户输入，2026-09-10。

### PRD-AI-001 — 知识库增强的流式草稿

- 用户价值：坐席快速获得可核对的建议回复。
- 要求：基于当前租户知识库和会话上下文生成流式草稿，P95 从“坐席请求生成”到“界面可见首 token”不超过 2 秒。
- 产品验收：在约定负载与样本集上验证延迟、引用相关性和回答质量。
- State: confirmed；Source: 用户输入，2026-09-10。

### PRD-APPROVAL-001 — 人类保留发送权

- 用户价值：阻止未经审阅的模型输出直接触达访客。
- 要求：AI 输出始终是内部草稿；只有有权限的坐席显式确认最终文本后才可发送。
- 产品验收：UI、API、权限和端到端测试均无法绕过确认步骤。
- State: confirmed；Source: 用户输入，2026-09-10。

### PRD-KB-001 — 企业知识管理

- 用户价值：企业可以控制 AI 可引用的知识范围和版本。
- 要求：管理员可发布、更新、撤回知识；检索结果隔离到当前租户并展示引用。
- 产品验收：撤回内容不再用于新草稿；跨租户检索测试为零泄露。
- State: provisional；Source: 为实现用户要求采用的 MVP 默认。

### PRD-PRIVACY-001 — 企业数据不用于模型训练

- 用户价值：企业资料、会话和反馈不成为供应商训练数据。
- 要求：仅选择以合同、DPA 和产品配置明确承诺 API 输入输出不用于训练的供应商；平台自身也不得将企业数据用于跨客户训练。
- 产品验收：采购审查、配置检查和数据流审计均通过。
- State: confirmed；Source: 用户输入，2026-09-10。

### PRD-DEGRADE-001 — 模型故障时人工退化

- 用户价值：AI 依赖故障不阻断客服接待。
- 要求：模型超时、限流或不可用时关闭 AI 草稿入口并保持人工聊天、历史和发送能力。
- 产品验收：故障演练证明人工链路不依赖模型供应商。
- State: confirmed；Source: 用户输入，2026-09-10。

### PRD-COST-001 — 月度成本上限

- 用户价值：MVP 在小团队可持续运营。
- 要求：AI 与基础设施月度总支出不超过人民币 50,000 元；达到阈值时告警并限制非关键 AI 消耗，不限制人工聊天。
- 产品验收：月度账单、用量仪表板和限额演练。
- State: confirmed；Source: 用户输入，2026-09-10。
