# 容量、运维与成本规范

## 1. 容量基线

以下均为 **provisional**，上线前以封闭测试真实数据校准；任一指标连续 7 天偏差超过 50% 即重算容量与预算。

| 项目 | 基线假设 |
|---|---:|
| DAU | 20,000 |
| 每 DAU API 请求 | 60 次/日 |
| 日 API 请求 | 1.2M；平均约 14 RPS |
| 峰均比 | 8；设计常态峰值约 110 RPS |
| 压测峰值 | 330 RPS（常态峰值 3 倍） |
| 每日打卡人数 | 8,000（DAU 的 40%） |
| 带照片打卡 | 打卡的 30%，平均 1.2 张 |
| 规范化照片均值 | 1.2 MB/张，缩略图 120 KB |
| 新增媒体 | 约 3.5 GB/日、105 GB/月 |
| 6 个月照片在线量 | 约 630 GB（未计删除） |
| 推送任务 | 最高 20,000/日；15 分钟窗口内 5,000 峰值 |

数据库保守按 5–15 GB/月增长（含索引和审计），连接峰值上限需在压测确定。照片上传流量不经过 API；客户端并发限制和对象存储回调防止 API 被大文件拖垮。

## 2. 生产资源起步规格

- API：2 个 2 vCPU/4 GB 实例，跨可用区，自动伸缩 2–6。
- Worker：1–2 个 2 vCPU/4 GB 实例；提醒和媒体使用独立队列及并发上限。
- PostgreSQL：托管高可用，起步 2–4 vCPU/8 GB、200 GB SSD、PITR 15 分钟粒度。
- Redis：托管主从 1–2 GB；设置 maxmemory/淘汰策略，业务事实不只存在 Redis。
- 对象存储：私有桶、隔离/成品前缀、生命周期、CDN 缩略图分发。
- 日志：结构化采样；错误和安全事件全量，成功请求按比例并聚合指标。

该规格为 **provisional**。重评触发：CPU/内存 > 70% 持续 15 分钟、DB P95 查询 > 100 ms、连接 > 70%、队列最老任务 > 2 分钟、存储 IOPS > 70%，或压测不能达到 330 RPS。

## 3. 月度基础设施预算（人民币）

| 类别 | 目标上限 | 控制手段 |
|---|---:|---|
| API + worker 计算 | ¥2,000 | 包年/预留基础量，峰值按量；非生产夜间停机 |
| PostgreSQL 高可用 | ¥2,400 | 合理实例/存储，慢查询治理，避免过早读副本 |
| Redis 高可用 | ¥600 | 小规格起步；限制缓存值与队列积压 |
| 对象存储 + CDN + 图片处理 | ¥800 | 客户端压缩、缩略图、生命周期、带宽告警 |
| LB/WAF/DNS/证书 | ¥450 | 使用云原生基础规则，证书自动续期 |
| 日志/指标/追踪 | ¥700 | 采样、30 天热存、指标优先于全文日志 |
| 备份与安全基础项 | ¥400 | 30 天轮转、KMS/secret、恢复演练 |
| 弹性与价格波动预留 | ¥650 | 约 8% 缓冲 |
| 合计 | **¥8,000** | 硬预算告警：70%/85%/100% |

预算口径 **provisional**：不含短信验证码、第三方内容审核人工/调用、应用商店账号、ICP备案/等保测评、研发测试设备与人力；这些属于业务可变成本或一次性合规成本，需单独预算。若采购口径要求全部计入 8,000 元，S1 必须重排预算并优先引入登录设备信任以降低短信量，不能削减备份和安全基线。

预算重评：月预测 > ¥7,200、照片新增 > 200 GB/月、CDN 出流 > 2 TB/月、日志 > 300 GB/月、DAU > 30,000，或任一供应商调价 > 15%。FinOps 每周看趋势、每月做按模块归因。

## 4. SLO 与错误预算

| 服务指标 | 月度目标 | 测量口径 |
|---|---:|---|
| 核心 API 可用性 | 99.9% | 合法请求非计划性 5xx/超时；约 43.8 分钟错误预算 |
| 打卡创建成功率 | 99.9% | 服务端已接收的合法请求 |
| 核心 API 延迟 | P95 < 500 ms，P99 < 1.5 s | 不含媒体直传与外部短信送达 |
| 教练列表延迟 | P95 < 700 ms | 标准 20 条分页 |
| 提醒调度及时率 | 99% 在目标时间 ±5 分钟 | 排除用户设备离线/系统禁用通知 |
| 媒体处理 | 99% 在上传后 2 分钟完成 | 含扫描与缩略图 |

若 7 天消耗月错误预算 50%，暂停非可靠性发布；消耗 100%，仅发布修复/安全变更并完成复盘。

## 5. 监控与告警

### 5.1 必须监控

- Golden signals：请求量、错误率、延迟、饱和度；按版本、路由、平台聚合，不用手机号标签。
- PostgreSQL：CPU、连接、锁等待、慢查询、复制延迟、磁盘与备份结果。
- Redis/队列：内存、命中率、驱逐、失败率、最老任务年龄、死信数量。
- 媒体：上传会话完成率、处理耗时、拒绝率、孤儿对象、签名失败。
- 通知：计划数、抑制数、供应商成功/无效 token/限流、点击和关闭率。
- 客户端：无崩溃会话、启动时间、API 错误、同步队列积压；release 日志脱敏。
- 成本：日累计、月预测、存储/带宽/日志分项异常。

### 5.2 分级告警

- SEV-1 页面值班：核心 5xx > 5% 持续 5 分钟、打卡疑似丢失/越权、数据库不可用、对象桶公开。
- SEV-2 页面值班：核心 5xx > 1% 持续 10 分钟、P95 > 1.5 秒、提醒延迟 > 15 分钟、媒体队列 > 10 分钟。
- SEV-3 工单：预算预测 > 85%、无效设备 token > 10%、单个非核心接口退化。
- 告警必须有 owner、runbook、用户影响和静默规则；连续两周无行动价值的告警调整或删除。

## 6. 备份与灾备

- PostgreSQL：每日全备 + 连续日志/PITR；备份跨可用区、同大陆地域保存 30 天并加密。
- 对象存储：版本保护/软删除窗口 **provisional** 7 天，但隐私删除使用不可恢复删除或专用流程，不能被版本保护无限保留。
- 配置/基础设施：IaC、版本化配置、密钥引用，不把 secret 写入备份脚本。
- 目标：核心数据 RPO ≤ 15 分钟，核心服务 RTO ≤ 4 小时；**provisional**，当付费/SLA 合同或 DAU > 50,000 时评估 RTO ≤ 1 小时和跨地域灾备。
- 每月自动验证备份可读，每季度恢复到隔离环境；上线前进行一次完整恢复及删除墓碑重放演练。

## 7. Runbook 摘要

### 数据库高负载

确认用户影响 → 限制昂贵教练查询/批量操作 → 查锁和慢查询 → 必要时只读降级 → 扩规格 → 复盘索引/查询。禁止未备份直接 kill/改数据。

### 短信攻击或供应商故障

触发日预算熔断 → 提高风险挑战和冷却 → 允许已登录会话继续 → 切备用供应商（若配置） → 公告登录影响 → 核对账单和号码泄露范围。

### 推送积压

停止生成重复任务 → 确认供应商/队列 → 丢弃过期提醒而非洪峰补发 → 恢复后分批放量 → 清理无效 token。

### 媒体异常

关闭上传 kill switch，不影响文字打卡 → 隔离可疑 worker/对象 → 检查桶策略和签名 → 重建安全处理队列 → 若存在暴露，进入安全事件流程。

### 错误发布

冻结流水线 → 服务端/网页回退上一版本或关闭 flag → 数据迁移按预先兼容方案停止而非逆向破坏 → 验证核心旅程 → 记录时间线。

## 8. 值班与运营

- 上线首两周工程、产品、客服联合值守；其后至少后端/客户端各一名轮值升级联系人。
- 每个 SEV-1/2 在 2 个工作日内无责复盘，行动项有 owner/期限。
- 状态页/应用内公告提供事件更新；客服只使用经批准模板，不推测数据泄露范围。
- 每周容量/成本评审，每月 SLO 与权限复核，每季度恢复和供应商退出演练。
