# 6 个月交付与质量计划

## 1. 交付模型

- 周期：24 周，12 个双周 Sprint；每个 Sprint 结束提供可演示增量。
- 分支：短生命周期 feature branch + 主干集成；主分支始终可部署。
- 环境：开发、预发布、生产隔离；S4 起每 Sprint 至少一次预发布部署。
- 范围纪律：P0 上线必需，P1 有余量再做，P2 不进入 MVP。

人员容量 **provisional**：已知 3 名 Flutter；规划假设另有 2 名 TypeScript 后端、1 名产品/设计复合角色、1 名 QA（S4 起全职）、0.5 名 DevOps/安全支持。若 S1 末实际后端少于 2 人或 QA 不能在 S4 到位，立即将离线草稿、教练 CSV 导出等 P1 后移，并把托管服务/外部测试预算单列审批。

## 2. 里程碑

| Sprint / 周 | 交付 | 出口标准 |
|---|---|---|
| S1 / 1–2 | 产品澄清、信息架构、技术 spike、合规数据地图 | P0 故事可验收；Flutter Web、推送、图片直传 spike 通过 |
| S2 / 3–4 | 设计系统、仓库/CI、环境、OpenAPI 骨架、身份模型 | 三端可构建；开发环境一键部署；威胁建模 v1 |
| S3 / 5–6 | OTP 登录、会话、用户资料、隐私同意 | 认证集成测试与频控测试通过 |
| S4 / 7–8 | 计划模板/版本后端；会员计划日历只读 | 首个端到端垂直切片上预发布；QA 回归启动 |
| S5 / 9–10 | 教练计划编辑、发布与分配 | 权限隔离测试；10 人可用性测试 |
| S6 / 11–12 | 打卡创建/编辑、离线草稿基础 | 弱网与幂等测试；中期范围/性能评审 |
| S7 / 13–14 | 照片直传、处理、缩略图、删除 | 恶意文件、EXIF、越权和孤儿清理测试 |
| S8 / 15–16 | 提醒规则、调度、iOS/Android 厂商推送 | 真机矩阵送达验证；静默/退订/去重通过 |
| S9 / 17–18 | 教练看板、筛选、完成率；隐私导出/注销 | 聚合性能、照片访问审计、删除 E2E 通过 |
| S10 / 19–20 | 功能冻结、埋点、无障碍、兼容、压测与安全测试 | 无未完成 P0；3 倍峰值压测；高危漏洞为 0 |
| S11 / 21–22 | 1%→10%→30% 灰度、商店/备案材料、灾备演练 | SLO 连续 7 天达标；回滚/恢复演练通过 |
| S12 / 23–24 | 100% 上线、监控值守、问题收敛、移交 | DoD 全部签署；运维/客服 runbook 可用 |

每个里程碑保留约 15% 容量处理技术风险与缺陷；这不是额外范围预算。

## 3. 工作分工

### 3.1 Flutter 三人建议

- F1：会员核心旅程、路由/状态管理、客户端架构 owner。
- F2：教练 Web、响应式设计、设计系统 owner。
- F3：媒体、推送、原生集成、发布流水线 owner。
- 三人轮换 code review 和真机值班，避免单点；公共 packages 的 breaking change 需至少两人批准。

### 3.2 职责矩阵

| 决策/交付 | A 最终负责 | R 执行 | C 咨询 |
|---|---|---|---|
| MVP 范围/指标 | 产品负责人 | 产品/设计 | 技术、教练代表、QA |
| 架构/API/数据 | 技术负责人 | 后端 + 客户端 owner | 运维、安全 |
| 隐私与备案 | 运营主体负责人 | 法务/合规 | 产品、安全、云厂商 |
| 发布/回滚 | 技术负责人 | DevOps + 客户端发布 owner | QA、产品 |
| 上线放行 | 产品 + 技术共同负责 | QA 汇总证据 | 安全、运维、客服 |

## 4. Definition of Ready / Done

故事进入开发前必须有：用户价值、范围边界、可验证验收标准、错误/空态、埋点、数据分类、设计稿/接口契约、依赖和负责人。

故事完成必须有：

- 实现、代码评审、单元/组件测试及契约测试通过。
- 权限、失败、弱网、重复提交和可访问性场景覆盖。
- API/OpenAPI、迁移、指标/日志/告警与客服文案同步。
- 预发布验收；无新增严重/高危安全问题。
- feature flag 默认值、灰度规则和回滚方法记录。

## 5. 测试策略

| 层 | 范围 | 门禁 |
|---|---|---|
| 静态 | Dart/TS lint、类型、格式、secret/SAST/依赖扫描 | 每次 PR 必须通过 |
| 单元 | 领域状态机、时区、调度、权限策略、序列化 | 关键领域分支覆盖 ≥ 90%；全仓不以覆盖率代替质量 |
| 组件 | Flutter widget、NestJS module、DB repository | 核心页面四态；真实 PostgreSQL/Redis 容器 |
| 契约 | OpenAPI 请求/响应、移动端生成 client、事件 schema | breaking change 阻断合并 |
| 集成 | OTP mock、对象存储、队列/outbox、推送 adapter | 超时、重试、重复和供应商错误覆盖 |
| E2E | 登录→计划→打卡→教练查看；注销/删除 | iOS、Android、Web 每夜主路径 |
| 安全 | 越权、枚举、注入、恶意图片、签名 URL | S10 渗透；严重/高危为 0 |
| 性能 | 核心 API、批量分配、提醒峰值、媒体并发 | 20k DAU ×3 峰值，P95/SLO 达标 |
| 恢复 | DB PITR、对象恢复、删除墓碑重放 | S11 演练且 RPO/RTO 达标 |

## 6. 兼容测试矩阵

- iOS：最近两个大版本；至少一台小屏、一台当前主流、一台较旧设备。
- Android：8/10/12/14+；华为、小米、OPPO、vivo 各至少一台真机，另含低内存设备。
- Web：Chrome/Edge/Safari 最近两个稳定版，360/768/1024/1440 宽度；国产 Chromium 浏览器按流量补充。
- 网络：Wi-Fi、4G/5G、400 ms RTT、5% 丢包、断网恢复、上传中切后台。
- 时间：23:59/00:00、跨月/年、夏令时区（虽默认中国时区，仍避免错误假设）。

## 7. 测试数据

- 仅使用合成账号和许可图片；生产手机号/照片不得进入测试环境。
- 固定 persona：新会员、活跃会员、无计划会员、已撤回照片同意会员、教练 A/B、停用教练、管理员。
- 测试照片集覆盖 HEIC、透明 PNG、超大像素、伪造 MIME、损坏文件和含 EXIF/GPS 文件。
- 负载数据生成脚本可重复、可销毁，账号均以专用号段/标志隔离。

## 8. 发布与回滚

- 后端：蓝绿或滚动部署，数据库迁移向前兼容；错误率/延迟异常自动停止。
- Web：版本化静态资源，HTML 快速回退；CDN 缓存可精确刷新。
- 移动端：内部测试→1%→10%→30%→100%，每阶段至少观察 24 小时；服务端保留上一移动版本兼容。
- kill switch：照片上传、提醒发送、批量分配分别可关闭；关闭不破坏已有数据读取。
- 回滚触发：崩溃无故障率低于 99.5%、核心 API 5xx > 1% 持续 5 分钟、数据错写或越权任何一次；安全事件直接暂停相关功能。

## 9. 埋点与实验

核心事件：`signup_started/completed`、`plan_viewed`、`checkin_started/submitted/synced`、`photo_upload_started/ready/failed`、`reminder_configured/delivered/clicked/disabled`、`coach_plan_published/assigned`。

每个事件定义触发时机、属性 allowlist、owner、保留期与验证用例。用户 ID 使用分析专用不可逆标识；禁止自由文本、手机号、精确照片标识。MVP 仅支持 feature flag 灰度，不建设复杂 A/B 平台。
