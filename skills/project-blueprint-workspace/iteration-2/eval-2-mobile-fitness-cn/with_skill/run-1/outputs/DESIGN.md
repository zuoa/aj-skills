# 产品设计约束

## 关键界面与任务

| Surface | Audience/context | Primary job | State |
|---|---|---|---|
| 学员今日训练 | 手机、训练中、注意力分散 | 看清下一项动作并记录完成 | provisional |
| 学员打卡 | 手机/响应式 Web、可能弱网 | 确认今日状态并提交可恢复的打卡 | provisional |
| 登录 | 三端、键盘或触控 | 输入手机号/验证码并理解等待与错误 | provisional |
| 教练计划编辑 | 桌面 Web、高密度重复工作 | 为一个授权学员安全修改计划 | provisional |
| 教练学员列表 | 桌面 Web | 定位学员并识别近期进展/异常 | provisional |

## 视觉与信息架构

- 学员导航围绕“今日、计划、我的”；教练端围绕“学员、计划”。具体标签以可用性验证为准。
- 视觉主张是“清晰的训练节奏”：用排版和真实的组次/完成状态形成节奏，服务训练中快速识别，不从“健身感”推导霓虹、渐变或装饰图表。
- 唯一暂定识别元素是计划中的节奏刻度，只编码真实动作顺序或组次；若不能提高辨认则移除。
- 无品牌或竞品参考输入。借用 iOS/Android 的权限、返回、通知设置惯例；平台差异保持原生可理解。
- 避免玻璃卡片、超大圆角、任意编号、装饰仪表盘和夸张连续动效。字体用系统字体；颜色、密度、图像风格与品牌 token pending。

## 响应式与权限与平台行为

- Flutter iOS/Android 遵循各平台返回、安全区、文字缩放、照片与通知权限生命周期；拒权后提供系统设置路径，不重复强求。
- 响应式 Web 在窄屏单列、桌面保持合理行长；教练数据表支持键盘、可见焦点、表头和不依赖悬停的动作。
- 推送深链进入具体训练前重新验证会话和资源；Web 不假设具备等价推送能力。
- 离线可查看最近明确标记的缓存计划；打卡可进入“待同步”，照片是否离线排队由 `TBD-DESIGN-001`/技术风险验证决定。

## 状态矩阵

| Flow | Loading | Empty | Error/offline | Permission | Destructive |
|---|---|---|---|---|---|
| 手机登录 | 验证码倒计时可读 | 不适用 | 区分错误/过期/渠道失败 | 不适用 | 退出登录确认影响 |
| 今日训练 | 保留内容骨架 | 说明今日无计划 | 标记缓存时间和重试 | 无权不泄露计划 | 不适用 |
| 打卡/照片 | 分开显示保存与上传 | 提供首次打卡动作 | 待同步/冲突/上传失败分别处理 | 解释照片拒权与设置路径 | 删除照片/覆盖打卡需确认 |
| 推送 | 保存偏好进度 | 说明尚无提醒 | 渠道失败不改业务状态 | 拒权后不循环弹窗 | 关闭全部提醒确认范围 |
| 教练端 | 保留筛选/列 | 区分无学员与无匹配 | 保留编辑草稿并处理冲突 | 指明无关系/角色权限 | 计划覆盖显示对象和版本 |

## 无障碍、内容与 Emoji

按 WCAG 2.2 AA 作为 Web 暂定目标，并对 iOS/Android 屏幕阅读、动态字体、对比度、非颜色状态、触控目标、键盘/开关控制进行真机测试。健身动作图像/视频需要文字说明；状态不能只靠动效。

文案使用动作和结果，例如“完成今日打卡”“照片上传失败，打卡文字已保存”。不以羞耻、体型评价或连续打卡中断制造压力。团队编写标题、按钮、列表、状态与系统文案不使用 Emoji；当前无例外。

## 设计自检

节奏刻度只保留真实序列含义；没有指标来源则不画表现仪表盘。移除颜色和动效后计划、状态、权限与下一步仍须清楚。最高风险是三端离线/权限行为，须按状态矩阵做真机验收。
