# 产品设计约束

“现代、简洁、高级”不具备可验收性，不能作为视觉规范。以下方向只把已知的旧书检索、单册辨认与预订任务转成可评审约束；在没有品牌手册、参考图和用户研究的情况下，视觉身份保持 `provisional`。

## 目标用户、场景与主要任务

| Surface | 用户与场景 | 唯一优先任务 | Evidence | State |
|---|---|---|---|---|
| 店员库存工作台 | 店内桌面、键鼠、重复录入与核对 | 找到并准确修改一个具体单册 | 用户给定平台；旧书单册模型为暂定 | provisional |
| 店员预订队列 | 店内桌面、可能被顾客或电话打断 | 判断下一项待处理预订并安全变更状态 | MVP 范围 | provisional |
| 顾客搜索页 | 手机、单手操作、可能在路上或店内 | 迅速判断是否存在想要且可预订的单册 | 用户给定平台 | confirmed（平台） |
| 顾客单册详情 | 手机、需要比较品相与价格 | 理解这一册的差异并决定是否预订 | PRD-CATALOG-001 | provisional |
| 顾客预订确认 | 手机、输入联系资料 | 检查对象与资料后提交并保存编号 | PRD-RESERVE-001 | provisional |

## 体验原则

- 单册身份始终可见：题名之外持续显示单册编号、品相、价格和状态，避免把“同书”误认为“同一本实物”。
- 状态先于装饰：待处理、已确认、不可预订、已完成与同步失败必须有文字标签，不能只靠颜色。
- 重复工作可扫读：店员表格保持紧凑但不拥挤；批量能力在真实工作量确认前不进入 MVP。
- 高代价动作可恢复：拒绝、取消或标记完成前显示影响对象；可撤销性待业务规则确认。
- 搜索上下文不丢失：顾客从详情返回时保留关键词、筛选和滚动位置。

## 信息架构

### 店员桌面 Web

主导航仅含“库存”“预订”；账户和退出置于辅助区域。库存默认列表的主要任务是检索并定位单册，编辑在详情/侧面区域完成，保存后原位显示结果。预订默认按需要处理的状态排序，但具体优先规则属于 `TBD-RESERVE-001`。

### 顾客手机网页

层级为“搜索结果 → 单册详情 → 预订表单 → 结果”。首页不设置营销 Hero 或装饰性数据面板；首屏把搜索输入和可理解的范围说明放在前面。详情页将可预订性、品相和价格置于预订动作之前。

## 视觉方向

- 视觉主张与任务理由：采用“旧书目录卡”的编辑式秩序，以清晰的书目信息层级和克制的纸张色温帮助顾客辨认书、帮助店员扫读记录；这不是已确认品牌风格。
- 最多一个识别性元素：书目详情使用窄列“馆藏标签带”，只承载单册编号、品相与状态这些真实信息，不作纯装饰。该元素 `provisional`，需用线框测试其是否改善辨认。
- 参考依据：借用图书馆目录的元数据层级与书店价签的直接性；不声称参考了某个未提供的具体品牌或竞品。
- 明确避免：紫蓝渐变、玻璃卡片、超大圆角容器、重复胶囊、无业务依据的 01/02/03 编号、闪光/机器人符号、环境动画和装饰性仪表盘。它们不能解释单册差异或预订状态。
- 字体：正文和控件先使用平台系统无衬线字体；书名是否使用衬线字体待可读性和品牌方向验证，不下载未经批准的品牌字体。
- 色彩：中性纸白背景、深色正文和单一强调色为暂定语义框架；具体色值、暗色模式与品牌色均 pending。错误、警告、成功同时提供文字/图标线索。
- 布局：桌面工作台以数据密度和对齐为先；手机采用单列。圆角、阴影仅区分交互层级，不以大卡片包裹每个段落。
- 动效/图像：仅用短暂反馈解释保存、展开或状态变化并支持 reduced motion。书封来自库存资料时显示来源/占位和替代文字；不生成仿旧纹理冒充品牌资产。

## 设计 token 与组件

| Topic | Source/decision | Override policy | State |
|---|---|---|---|
| 字号/间距 | 基于可读层级与 4px 间距基元建立，最终数值由原型验证 | 不以“高级感”任意加大留白 | provisional |
| 颜色 | 语义 token：text/surface/border/action/status | 品牌色确认后映射，不改变语义 | provisional |
| 组件 | 优先采用可访问的 Web 基础组件；技术库待架构确认 | 只为单册标签带做产品特定组合 | provisional |
| 图标 | 一个统一、平台适配的线性图标集 | 陌生/关键动作配可见文字 | pending |

## UI 状态矩阵

| Flow | Loading | Empty | Error | Offline | Permission | Destructive |
|---|---|---|---|---|---|---|
| 库存列表 | 保留列结构并标注加载 | 说明尚无记录并提供“新增单册” | 保留查询并提供重试 | 显示数据可能陈旧，禁用保存 | 指明无库存权限 | 删除/下架需对象名称与确认 |
| 搜索 | 输入可用，结果区加载 | 区分“无库存”与“无匹配”，提供改词 | 保留关键词与筛选后重试 | 说明无法取得当前库存 | 不适用 | 不适用 |
| 预订提交 | 按钮显示处理中且防重复提交 | 不适用 | 说明是否已创建预订及下一步 | 提交前阻止并保留已填内容 | 不泄露他人预订 | 提交前显示单册与联系方式摘要 |
| 预订队列 | 保留筛选与行结构 | 说明当前没有待处理项 | 保留筛选并重试 | 禁用状态修改并显示陈旧标记 | 指明无处理权限 | 拒绝/取消需显示影响对象 |

## 无障碍与内容

- 目标：Web 按 WCAG 2.2 AA 设计和验收；最终适用范围待产品负责人确认。
- 桌面全键盘可达，焦点环清晰；手机触控目标间距和缩放不受阻；错误与字段建立程序化关联。
- 语义标题、表格表头、表单标签和状态 live region 按实际组件验证；书封替代文字描述识别价值，不重复相邻书名。
- 文案使用“单册”“预订”“确认”“拒绝”等稳定术语。按钮写具体动作，如“预订这册书”“确认预订”；错误说明发生了什么、是否保存以及下一步。
- 地区、语言、日期、币种、姓名和电话号码格式均 pending；布局预留文本扩展，不截断关键状态。

## 图标、图像与 Emoji

- Emoji policy: 团队编写的标题、列表、导航、按钮、状态和系统文案均不使用 Emoji。
- 当前无 Emoji 例外。用户生成内容若未来出现，原样存储但不能作为状态语义。
- 图标不能作为关键动作的唯一标签；纯图标按钮必须有可访问名称。

## 设计自检

- 产品特定性来自“单册元数据标签带”和旧书品相/状态层级；删除书店名称后仍能解释其服务的任务。
- 所有结构元素编码导航、书目层级、单册身份、状态或动作，没有装饰编号和无依据指标。
- 移除通用 SaaS Hero、渐变、玻璃、超大卡片、装饰图表、聊天式文案和 Emoji。
- 风险最高的假设是“目录卡”层级是否同时适合店员扫读和顾客理解；以两个端的线框任务测试验证，不以审美投票代替。
