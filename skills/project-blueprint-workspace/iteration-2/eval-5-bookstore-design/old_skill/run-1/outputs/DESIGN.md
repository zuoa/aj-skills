# 产品设计约束

老板提供的“现代、简洁、高级”不能直接转成可验收设计。由于没有品牌手册、参考图或用户研究，以下视觉方向均为 `provisional`，高保真设计前需要确认。

## 用户与体验原则

- 店员在桌面 Web 中高频录入、检索和修改单册，需要信息密度、键盘效率和保存状态可见。
- 顾客在手机网页中搜索、比较品相和价格、提交预订，需要单列流程、清晰动作和低输入负担。
- 同一书目可能有多个实物副本，书目、单册编号、品相、价格和状态应持续可见。
- 错误、空状态、离线和权限问题应说明发生了什么与下一步，不只靠颜色表达。

## 信息架构与关键界面

### 店员桌面 Web

主导航包括库存、预订和账户。库存列表支持题名、作者、ISBN 与单册编号检索，进入单册详情后编辑品相、价格和状态；主要任务是快速找到并准确更新单册。预订列表集中展示待处理项，详情允许确认、拒绝或完成；主要任务是安全处理下一项预订并看到操作结果。

### 顾客手机网页

流程为搜索、结果、单册详情、预订表单、结果。搜索页主要任务是找到可预订单册；详情页主要任务是比较品相、价格与状态；表单主要任务是确认对象和联系方式后提交。返回结果列表时保留关键词与筛选。

## 视觉方向

- 风格：克制的编辑式书店气质，使用温暖中性色、深色正文和低饱和强调色。具体色值与品牌适配尚未确认。
- 排版：正文和控件优先使用系统无衬线字体，书名可以试验易读的衬线展示字体；最终字体需验证中文/拉丁字符覆盖和加载成本。
- 布局：桌面以对齐清晰的表格和详情面板为主，手机使用单列卡片。通过字号、间距、边框与轻微阴影区分层级。
- 图像：库存有合法书封时展示并提供替代文字；缺图使用中性占位，不虚构出版社或品牌资产。
- 动效：只为保存反馈、展开和页面转换使用简短动效，支持 reduced motion。
- 禁忌：不使用与阅读任务无关的强烈渐变、炫技动画或数据图表；不因“高级”而牺牲信息密度和可读性。

## 设计 token 与组件

| Topic | Decision | State |
|---|---|---|
| Typography | 系统字体为默认；展示字体待验证 | provisional |
| Color | 中性表面、深色文本、一个操作强调色、语义状态色 | provisional |
| Spacing/grid | 4px 基元；桌面内容栅格和手机单列按原型调整 | provisional |
| Radius/elevation | 小到中等圆角，阴影仅用于浮层和层级 | provisional |
| Components | 采用可访问基础组件库，产品特定组件仅用于单册信息 | pending |
| Icons | 统一图标集；陌生或关键动作配文字 | pending |

## 响应式与平台行为

- 店员端优先键鼠与桌面宽度；表格列按任务优先级收缩，受支持最小宽度需盘点设备后确认。
- 顾客端单列布局，输入类型匹配字段，主要操作易于触达并避开安全区。
- 断点由表格溢出、表单行长和导航变化决定，而不是仅按常见设备宽度套用。
- 文本允许扩展；关键标题、状态和价格不得截断到无法理解。

## UI 状态矩阵

| Flow | Loading | Empty | Error | Offline | Permission | Destructive |
|---|---|---|---|---|---|---|
| 库存列表 | 保留列结构 | 提供新增入口 | 保留查询并重试 | 标记可能陈旧，禁写 | 说明无权限 | 下架/删除需确认对象 |
| 搜索 | 输入保持可用 | 提供调整关键词建议 | 保留查询并重试 | 说明不可取得当前库存 | 不适用 | 不适用 |
| 预订 | 防重复提交 | 不适用 | 说明是否成功创建 | 保留已填内容 | 不泄露他人数据 | 提交前核对单册和联系信息 |
| 预订队列 | 保留筛选和行结构 | 说明无待办 | 刷新当前状态 | 禁止状态修改 | 说明无处理权限 | 拒绝/取消需确认 |

## 内容与无障碍

- Web 以 WCAG 2.2 AA 为暂定目标；键盘顺序、可见焦点、缩放、触控目标、对比度和非颜色提示需测试。
- 标题、表格、表单标签与错误关联使用语义结构；图标按钮有可访问名称。
- 文案直接使用“单册”“预订”“确认”“拒绝”等领域词；按钮描述动作，错误说明结果和恢复方法。
- 地区、语言、日期、币种、姓名与电话格式尚未确认，布局需容纳文本扩展。
