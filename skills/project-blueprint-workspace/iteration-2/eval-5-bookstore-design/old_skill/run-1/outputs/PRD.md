# 独立旧书店库存与预订 SaaS 产品需求

## 文档状态

工作名“旧书库存与预订”。已确认的输入只有业务类型、店员桌面 Web、顾客手机网页；其余均为暂定或待决定。

## 问题和用户

- 店员需要在高密度桌面界面中快速建档、定位单册旧书、修正库存状态并处理预订。
- 顾客需要在手机上检索可售书、理解品相与库存状态、提交预订并获得可核对的结果。
- 旧书按单册管理：同一书目下的不同副本可能有不同品相、价格和状态。此为满足题述业务的 `provisional` 模型，需由老板确认。

## MVP 与非目标

MVP 包括单册库存、检索筛选、顾客预订、店员确认/拒绝/完成预订和审计记录。首版不包含在线支付、配送、会员积分、多门店调拨、原生 App 或自动估价。

## 核心旅程

| 旅程 | 角色 | 成功结果 | 状态 |
|---|---|---|---|
| 建立/修改单册 | 店员 | 可检索记录包含书目信息、品相、价格与状态 | provisional |
| 查找旧书 | 顾客 | 在手机上确认匹配单册及当前可预订性 | confirmed（范围） |
| 提交预订 | 顾客 | 获得不泄露他人信息的预订编号与后续说明 | provisional |
| 处理预订 | 店员 | 冲突被阻止，状态变化可追溯 | provisional |

## 产品需求

### PRD-CATALOG-001 — 单册库存

- 用户价值：店员可区分同一版本的不同实物。
- 要求：记录书目、单册编号、品相说明、价格和库存状态，允许受控修改。
- 验收：同书目多副本可分别查看与更新。
- State: provisional

### PRD-SEARCH-001 — 移动检索

- 用户价值：顾客无需到店即可判断是否值得预订。
- 要求：按题名、作者或 ISBN 检索，并按可预订状态筛选；结果展示单册差异。
- 验收：手机窄屏上可完成检索、筛选和查看详情。
- State: provisional

### PRD-RESERVE-001 — 顾客预订

- 用户价值：顾客可以锁定一册待到店取书。
- 要求：顾客提交必要联系信息后申请预订；系统明确成功、冲突或失败。
- 验收：同一单册不能产生两个同时有效的预订。
- State: provisional

### PRD-RESERVE-002 — 店员处理

- 用户价值：店员可在一个工作队列中确认、拒绝和完成预订。
- 要求：每次状态变化显示操作者、时间与结果。
- 验收：非法状态转换被阻止并解释恢复方式。
- State: provisional

### PRD-ACCESS-001 — 角色边界

- 用户价值：公开目录与店内操作数据分离。
- 要求：顾客只能访问公开目录和自己的预订结果；店员操作需要登录。
- 验收：未授权请求不显示库存成本、其他顾客资料或管理操作。
- State: provisional

## 成功衡量

不虚构转化率、延迟或节省时间。上线前由老板选择基线与目标；MVP 验收先以任务完成、库存冲突防止和关键流程可访问性为证据。
