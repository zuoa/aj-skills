# 产品设计约束

## 受众、情境与首要任务

| Surface | Audience/context | Primary job | Evidence | State |
|---|---|---|---|---|
| 告警队列 | 值班开发人员；可能处于高压、多窗口环境 | 找到当前需处理且数据可信的告警 | PRD-ALERT-001 | confirmed |
| 告警工作台 | 值班人员与事件负责人 | 在同一上下文核对影响证据 | PRD-IMPACT-001 | confirmed |
| 回滚抽屉/页面 | 有权限的执行者与批准者 | 明确目标、风险与前置条件后发起动作 | PRD-ROLLBACK-001 | confirmed |
| 窄屏只读视图 | 临时查看状态的开发人员 | 查看关键信息与跳转来源，不承担默认回滚路径 | 平台假设 | provisional |

主要输入模式暂定为桌面键盘和鼠标；设备、浏览器及无障碍技术范围由 `TBD-PRODUCT-003` 确认。

## 体验原则

| 原则 | 用户后果 | 反模式 | 状态 |
|---|---|---|---|
| 先证据，后动作 | 影响证据和缺口始终位于回滚入口之前 | 以醒目按钮替代判断上下文 | provisional |
| 时间与来源可见 | 每条动态信息都能判断“来自哪里、何时更新” | 只有旋转加载图或模糊的“实时”字样 | provisional |
| 风险与权限不隐身 | 禁用、拒绝、审批中均说明原因与下一步 | 灰掉按钮但不解释 | provisional |
| 高密度但有稳定扫描线 | 相同字段在列表、详情和确认页保持位置与术语 | 每块内容都做成独立圆角卡片 | provisional |
| 人掌握最终控制 | 建议与事实分层，回滚需显式复核 | 聊天回答直接附“自动修复”按钮 | provisional |

## 信息架构与旅程

全局导航只包含 MVP 必需区域：`告警`、`执行记录`；服务详情从上下文进入，不新增装饰性首页或指标总览。默认入口是告警队列，不建立“欢迎页”。

| Area/screen | User goal | Entry/exit | Related SPEC | State |
|---|---|---|---|---|
| 告警队列 | 筛选、排序并选中告警 | 默认入口；进入告警工作台 | SPEC-ALERT-001, SPEC-ALERT-002 | provisional |
| 告警工作台 | 查看告警、证据、影响项和当前发布 | 从队列进入；进入确认或来源系统 | SPEC-IMPACT-001, SPEC-IMPACT-002 | provisional |
| 回滚确认 | 核对环境、版本、影响、权限和批准 | 从已确认影响进入；提交或返回 | SPEC-ROLLBACK-001, SPEC-ROLLBACK-003 | provisional |
| 执行详情 | 查看步骤、结果、审计及恢复动作 | 提交后进入；返回告警或来源系统 | SPEC-ROLLBACK-002 | provisional |

### 告警队列

- 两栏结构：左侧为可折叠筛选区，右侧为数据表；不使用同尺寸卡片网格。
- 首列为严重度文字和图标，其后固定为告警、服务/环境、状态、新鲜度、负责人、开始时间。
- 默认排序规则由 `TBD-SPEC-001` 决定；用户切换排序后，当前规则可见且可恢复。
- 行展开只给出分诊所需摘要；完整证据进入工作台，避免一行塞入全部内容。

### 证据轨道

唯一的标志性装置是“证据轨道”：沿一条垂直主轴依次放置告警信号、受影响对象、当前发布和候选回滚。每个节点必须代表真实对象或决策阶段，连接线仅在存在已知关系时出现。

- 实线表示来源确认的关系，虚线表示系统推断，断口加文字表示缺失或冲突；不能靠颜色单独区分。
- 每个节点附来源、绝对时间及状态；选择节点时右侧证据检查器显示原始字段和来源链接。
- 轨道服务于“从信号追到可执行目标”，因此不用于首页装饰、背景动画或与对象无关的粒子效果。
- 如果 `TBD-AI-001` 决定引入模型，模型建议只能作为标记为“建议”的可折叠节点，展示依据、模型/提示版本及不确定性；无依据时不显示建议。

### 影响确认流

1. 用户在证据轨道查看受影响对象及冲突/缺失。
2. 用户逐项选择“确认”“驳回”或“待补证据”，必要时填写理由。
3. 系统在固定底栏汇总已核对、待处理和已变化项；只有满足 `TBD-SPEC-002` 后才提供“完成影响确认”。
4. 提交时若证据版本变化，停留在当前页并把变化前后值并列显示。

### 回滚执行流

回滚使用独立页面或占据至少半屏的抽屉，不使用小型模态框。顺序固定为：目标环境与服务、当前/候选版本、影响摘要、前置检查、授权/审批、确认输入、提交。

- 主按钮文案为“发起回滚”，不用“确认”“继续”等含糊词。
- 生产环境采用环境名输入或等价的不可误触确认方式，具体策略由 `TBD-SPEC-003` 决定。
- 提交后立即切换为执行记录，不用庆祝动画；状态未知时不呈现为失败，也不允许无提示重复发起。

## 视觉方向

- 视觉主张与任务依据：采用“飞行记录仪式的操作界面”，用稳定坐标、窄分隔线、等宽标识符和可追溯时间表达系统正在记录事实；未来感来自信息响应与精密状态，不来自科幻装饰。
- 标志性装置：仅使用“证据轨道”。其节点和连线都编码来源、关系和决策阶段。
- 参考取向：借用终端的可扫描标识符、事件日志的时间秩序和部署流水线的阶段关系；不复制任何未提供品牌资产。
- 明确避免：玻璃拟态、渐变光晕、机器人/大脑图像、星光粒子、超大标题、统一圆角卡片、无数据依据的图表、聊天框作为首页、装饰性 `01/02/03` 编号。
- 字体角色：系统无衬线字体用于正文与操作；`ui-monospace` 用于时间、版本、执行 ID 和数值。表格数字使用等宽数字。避免为视觉效果引入远程字体依赖。
- 颜色语义：深色主题为暂定默认，背景 `#0B0F14`、工作面 `#121923`、主文字 `#E7EDF5`、次文字 `#9AA8B7`、交互强调 `#67D9E8`；危险、警告、成功、未知需分别配文字与图标。所有实际组合须通过 WCAG 对比度自动检查后才能锁定。
- 间距/网格/密度/圆角/层级：4px 基础单位；桌面 12 列；表格行高暂定 40px，可切换 48px 舒适密度；半径 4px，仅容器边界和控件使用；以边框、背景明度和留白区分层级，避免大面积阴影。
- 动效与图像：唯一编排动效是新证据进入轨道时在 180–240ms 内从来源位置淡入并高亮一次，具体时长 provisional；减少动态时直接出现。除服务头像或用户提供资产外不使用插画。

## 图标、图像与 Emoji

- 图标源与标签：provisional 采用 Lucide 或现有产品图标库二选一，由 `TBD-DESIGN-001` 锁定；关键操作必须同时显示文字，纯图标按钮有可访问名称和提示。
- 图像来源、权利与无障碍：MVP 不需要装饰图像；用户提供的服务标识需确认使用权并有文字名称。
- Emoji 策略：团队编写的 UI、状态、导航和系统文案不使用 Emoji。

Emoji 例外：not-applicable；当前没有经批准且能改善运维任务的例外。

## 设计 Token 与组件

| Topic | Source/decision | Override policy | State |
|---|---|---|---|
| 颜色 | 上述语义 token，不以品牌色承载危险含义 | 仅在对比度测试通过且语义不冲突时覆盖 | provisional |
| 字体 | 系统 sans + `ui-monospace` | 不为风格引入阻塞渲染的远程字体 | provisional |
| 组件基线 | 选择可访问的无样式/低样式组件原语，具体库取决于技术栈 | 业务组件可组合，不 fork 基础可访问行为 | pending (`TBD-ARCH-003`) |
| 表格 | 原生语义表格或具备等价语义的数据网格 | 虚拟化仅在真实数据量证明需要时引入 | provisional |
| 状态标签 | 矩形标签加文字与图标；不重复使用药丸容器 | 不允许颜色作为唯一编码 | provisional |

## 无障碍与内容

- 无障碍目标：provisional 采用 WCAG 2.2 AA；若组织标准更高则由 `TBD-DESIGN-001` 更新。
- 键盘/焦点/触控：跳过链接、可见焦点、不使用焦点陷阱；表格行内操作可从键盘到达；动态更新不抢焦点；触控目标不小于适用 AA 要求。
- 对比度与非颜色线索：状态同时有文字和图标/线型；高对比模式下保留边界；自动检查 token 与实际组件组合。
- 屏幕阅读器/语义：列表和表格保持语义结构；证据轨道提供等价有序列表；动态状态用适当 live region，频繁日志默认不逐条播报。
- 本地化与文本扩展：日期、数字、时区经 locale 格式化；为 200% 文本扩展预留布局；支持语言、RTL 和地区仍为 `TBD-PRODUCT-003`。
- 内容语气与术语：短、直接、说明结果；稳定使用“告警、影响确认、发起回滚、状态未知”。禁用按钮旁说明原因，错误同时说明动作是否发生。

## 设计自检

- 不能原样迁移到无关产品的选择：证据轨道严格对应告警信号、服务影响、部署版本和回滚阶段；回滚确认固定显示环境/服务/版本三元组。
- 结构编码：列表列表示分诊字段；轨道节点表示证据或阶段；线型表示关系类型；固定底栏表示未完成项与可执行性。
- 已删除/拒绝的生成式套路：聊天首页、霓虹渐变、玻璃卡片、机器人、装饰粒子、假数据图表、无依据置信环、过量药丸标签。
- 最危险假设与验收：暗色高密度界面可能降低可读性。以含长文本、色觉差异、高对比模式、200% 缩放和高压任务脚本的可用性测试验证；参与者和通过标准由 `TBD-DESIGN-001` 确定。
