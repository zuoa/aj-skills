# Development Planning Writer

面向政府、园区、事业单位、咨询研究机构的区域发展规划与地方专项规划写作技能。

它不是泛泛而谈的“行业文章生成器”，也不是招商口号或企业战略 PPT 代笔工具。目标是形成一份更接近正式规划文本的工作稿：规划属性清楚，依据完整，目标可量化，任务与项目闭环，实施路径和评估机制可落地。

## 先读什么

- 先读 [references/planning-rules.md](references/planning-rules.md)，确认法定属性、编制程序、硬约束和常见刚性要求。
- 起草正文前，按规划类型读取 [references/structure-templates.md](references/structure-templates.md)。
- 设计目标、指标、项目库和实施矩阵前，读取 [references/indicator-and-projects.md](references/indicator-and-projects.md)。
- 需要借鉴成熟写法、章节组织或指标表达时，读取 [references/example-patterns.md](references/example-patterns.md)。
- 定稿前，读取 [references/self-checklist.md](references/self-checklist.md)。

## 适用任务

- 起草 `区域发展规划`
- 起草 `地方专项规划`
- 起草某市、某区、某园区、某功能片区的 `“十五五”规划`
- 起草规划 `编制说明`、`征求意见稿`、`专家论证稿`
- 设计 `指标体系`、`重大项目清单`、`重点任务分工表`
- 对既有规划初稿补充上位规划、最新政策、统计数据和对标案例后重写

默认不用于：

- 企业经营战略
- 商业计划书
- 投融资路演材料
- 招商宣传文案
- 国土空间总体规划或详细规划
- 单纯新闻通稿、讲话稿、宣传稿

## 自动判型

先判断是 `regional` 还是 `specialized`，再动笔：

- `regional`：对象是跨行政区、都市圈、城市群、片区、园区协同区、沿线经济带等“特定区域”；重点写战略定位、空间格局、功能分工、协同机制、跨区域项目和公共服务/生态/安全协同。
- `specialized`：对象是教育、科技、产业、交通、文旅、养老、数字化、生态环境等“特定领域”；重点写发展基础、总体要求、指标体系、重点任务、重大工程项目和保障措施。

如果用户给的是模糊主题，先在 `00-brief.md` 中固定：

- 规划类型
- 规划层级
- 规划主体
- 规划期
- 适用地域
- 是否需要正式报批材料

不能一边按区域规划写空间协同，一边又按专项规划写部门任务而不说明主从关系。

## 默认设置

- 默认规划期：`5` 年，并明确 `基期年 / 目标年 / 展望年`
- 默认研究方式：联网补充公开资料，优先政府、人大、统计、公报、上位规划原文
- 默认正文长度：
  - `regional`：`12000-22000` 字
  - `specialized`：`8000-18000` 字
- 默认验证轮次：`2` 轮；涉及强时效政策、密集指标、重大项目投资测算时升到 `3` 轮
- 默认终稿：`markdown`
- 默认输出目录：`planning-drafts/{slug}-{timestamp}/`

如果用户明确说“不联网”“只基于现有材料”，可以跳过外查，但必须在 `00-brief.md` 和终稿中写清证据边界。

## 核心原则

1. 先定规划属性，再写内容。规划类型、层级、法定依据和审批路径不清，正文越长风险越大。
2. 下位规划服从上位规划，同类规划相互协调；发展规划是遵循，国土空间规划提供空间保障。
3. 一份规划只解决一个对象和一个主线，不把“总体规划、专项规划、实施方案、行动计划”混写。
4. 规划期、基期年、目标年、展望年、口径范围必须明确，指标不能漂移。
5. 没有依据的目标不写，没有验证过的项目不硬塞，没有上位支撑的提法不用。
6. `regional` 重点是定位、布局、协同和机制；`specialized` 重点是目标、任务、项目和政策工具。
7. 任务、工程、项目、政策、机制、责任主体要闭环，不能只有方向没有抓手。
8. 项目库不是愿望清单。项目至少要说明必要性、成熟度、牵头主体和预期贡献。
9. 语言要像规划文本，不像论文、招商稿、讲话稿或宣传材料。
10. 用户要求“可报批版本”时，可以生成接近正式送审的工作稿，但不得暗示已经完成法定审批程序。

## 输出文件

为每次任务创建目录：`planning-drafts/{slug}-{timestamp}/`

- `00-brief.md`：任务约束、规划属性、周期、地域、是否联网
- `01-planning-basis.md`：规划依据矩阵、上位衔接、同级衔接、程序要求
- `02-terms.md`：术语表、机构和政策名称统一
- `03-search-plan.md`：检索问题、关键词、来源优先级、时间边界
- `04-source-log.md`：来源清单、URL、发布日期、可用要点
- `05-diagnosis.md`：发展基础、主要问题、约束条件、对标结论
- `06-indicators.md`：目标体系、指标表、测算逻辑、口径说明
- `07-project-pool.md`：重大工程项目、成熟度、牵头主体、实施时序
- `08-outline.md`：章节结构、标题、主线和章节任务
- `09-draft-v1.md`：初稿
- `10-review-round-1.md`：第一轮校验
- `11-draft-v2.md`：修订稿
- `12-review-round-2.md`：第二轮校验
- `13-final.md`：定稿
- `14-implementation-matrix.md`：任务分工、年度推进和评估安排

按需追加：

- `15-compilation-note.md`：编制说明、衔接说明、未采纳意见说明
- `16-opinion-log.md`：征求意见及采纳情况
- `17-risk-note.md`：环境影响、社会稳定、合法性/公平竞争等需补做事项提示

如果用户只要聊天窗口结果，仍然照常保存定稿文件，并在回复中给出路径。

## 正文与附件排版

正文以层次清晰的章节写作为主，不追求花哨格式。

默认写法：

- 正文用 `##`、`###` 组织章节
- 指标表、项目表、实施矩阵允许使用 Markdown 表格
- 非必要不做大而宽的对比表；对照分析优先卡片化分块
- 所有表格字段名保持稳定，避免同一指标在不同文件换口径换名称

## 工作流

### Step 1: 固定规划属性，写入 `00-brief.md`

优先从用户对话直接提取，不要因为默认项反复追问。至少确认：

- 规划名称
- 规划类型：`regional` / `specialized`
- 规划层级：省 / 市 / 区县 / 园区 / 跨区域
- 规划主体与使用场景：正式文本 / 领导汇报底稿 / 征求意见稿 / 研究支撑稿
- 规划期：基期年、目标年、展望年
- 目标地域和统计口径
- 是否必须联网，是否要求最新政策和最新数据
- 用户已有材料
- 是否需要项目库、指标表、编制说明等配套件

如果规划属性模糊，先给出 `1-2` 个合理判型并自行选择更稳妥的一种继续，不要停在空泛讨论。

### Step 2: 建立规划依据矩阵，写入 `01-planning-basis.md`

先读取 [references/planning-rules.md](references/planning-rules.md)。

至少梳理：

- 党中央、国务院重大部署
- 国家和省级上位规划
- 同级发展规划
- 同级或上级相关专项规划
- 国土空间规划或空间管控要求
- 法定程序要求：立项、征求意见、专家论证、衔接审查、合法性/公平竞争/环评/风险评估等

`01-planning-basis.md` 至少写清：

- 规划属性判断依据
- 上位规划清单
- 必须承接的目标、指标、重大任务
- 可能冲突的同类规划或政策边界
- 本次草稿尚未完成的法定程序事项

### Step 3: 统一术语，写入 `02-terms.md`

优先统一：

- 规划名称、地区名称、机构名称
- 政策文件全称与简称
- 产业、行业、公共服务和治理术语
- 指标名称、统计口径、单位

执行原则：

- 首次出现用官方全称
- 指标名称尽量采用统计制度或上位规划既有表述
- 同一术语不随意换同义词
- 用户材料里的口语提法可保留为线索，但不直接进入终稿

### Step 4: 制定检索计划，写入 `03-search-plan.md`

检索至少覆盖五类问题：

1. 发展基础和现实问题是否真实存在
2. 上位规划、政策和法定约束是什么
3. 可量化的现状数据和目标口径是什么
4. 哪些同类地区已有成熟做法
5. 已出台政策是否已经覆盖拟写建议，避免重复造概念

来源优先级：

1. 党中央、国务院、部委、省市政府、人大法规
2. 发展改革、统计、行业主管部门、公开年报公报
3. 正式规划文本与政策解读
4. 权威媒体和专业机构
5. 学术研究或行业报告

强时效内容优先近 `1-3` 年；法规、规划原文可适度放宽。

### Step 5: 联网搜集资料，写入 `04-source-log.md`

至少收集 `8` 个有效来源；复杂任务争取 `12-20` 个。

对每个来源记录：

- 标题
- 原文 URL
- 发布机构
- 发布日期
- 可信度
- 可用要点
- 将用于哪一章节

要求：

- 能找到原始发布页，就不用转载页
- 事实、判断、推演分开
- 旧数据只用于历史比较，不直接支撑当前结论
- 任何 AI 给出的链接、数字、案例都必须复核

### Step 6: 做基础诊断与对标，写入 `05-diagnosis.md`

`05-diagnosis.md` 不是长篇综述，而是为目标和任务提供依据。至少包含：

- 发展基础
- 主要短板或堵点
- 机会窗口与外部约束
- 与先进地区或同类地区的差距
- 对规划主线的判断

写法要求：

- 先事实后判断
- `regional` 重点分析空间结构、节点功能、要素流动、协同机制
- `specialized` 重点分析行业基础、供需矛盾、能力短板、制度堵点

### Step 7: 设计目标、指标和项目库，写入 `06-indicators.md` 与 `07-project-pool.md`

先读取 [references/indicator-and-projects.md](references/indicator-and-projects.md)。

指标至少写清：

- 指标名称
- 指标属性：`约束性 / 预期性 / 监测性`
- 单位
- 基期值
- 目标值
- 测算逻辑或来源口径
- 牵头部门

项目库至少写清：

- 项目名称
- 对应任务
- 建设或推进内容
- 成熟度：`谋划 / 前期 / 在建 / 储备`
- 实施时序
- 牵头主体
- 预期成效
- 目前证据边界

没有依据的投资额、土地规模、产值拉动，不要硬写。

### Step 8: 生成结构大纲，写入 `08-outline.md`

起草前按规划类型读取 [references/structure-templates.md](references/structure-templates.md)。

要求：

- `regional` 大纲必须体现定位、格局、功能分工、协同任务、跨区域机制
- `specialized` 大纲必须体现总体要求、发展目标、重点任务、重大工程项目、保障措施
- 标题使用规范公文式命名，不追求“爆款标题”
- 每章先定义“本章回答什么问题”，再写正文

### Step 9: 生成初稿，写入 `09-draft-v1.md`

初稿先把结构和依据落稳，不追求辞藻。

执行原则：

- 每个章节都有明确功能，不写万能过渡段
- 目标之后要有任务，任务之后要有工程或政策工具，最后要有实施机制
- `regional` 不可把跨区域规划写成单一行政区部门分工清单
- `specialized` 不可只有原则性表述，没有指标和项目支撑
- 对无法确认的数字、时间或项目状态，用审慎表述并标记待核

### Step 10: 进行两轮校验，写入 `10-review-round-1.md` 与 `12-review-round-2.md`

定稿前必须读取 [references/self-checklist.md](references/self-checklist.md)。

第一轮重点查：

- 规划属性和上位衔接是否成立
- 目标、指标、任务、项目是否闭环
- 事实、数据、年份、机构名称是否准确
- 章节逻辑是否完整

第二轮重点查：

- 语言是否像规划文本
- 是否存在空话套话、宣传腔、论文腔
- 是否把愿景写成确定性承诺
- 是否遗漏实施机制、评估机制、责任分工

涉及最新政策、重大投资、强约束指标或敏感公共议题时，增加第三轮时效校验。

### Step 11: 形成定稿与实施矩阵，写入 `13-final.md` 与 `14-implementation-matrix.md`

`13-final.md` 是用户可直接继续加工的主文本。

`14-implementation-matrix.md` 至少包含：

- 重点任务
- 关键举措
- 牵头单位
- 配合单位
- 时间节点
- 对应指标或项目
- 评估方式

如果用户要求送审配套材料，再补：

- `15-compilation-note.md`
- `16-opinion-log.md`
- `17-risk-note.md`

## 何时必须补做程序提示

如果用户要求“正式报批版”“政府印发版”“可直接上会版”，必须明确提示以下程序性事项是否已完成：

- 立项或目录清单纳入
- 征求意见
- 专家论证
- 衔接审查
- 合法性审查
- 公平竞争审查
- 环境影响评价
- 社会稳定风险评估

这类事项可在 `15-compilation-note.md` 或 `17-risk-note.md` 中写成“已完成 / 待完成 / 不适用”。

## 终稿标准

只有同时满足以下条件才输出定稿：

1. 规划类型、层级、周期、口径清楚
2. 与上位规划和同级相关规划不冲突
3. 目标、指标、任务、项目、机制基本闭环
4. 关键事实、政策、年份、机构名称可复查
5. 正文像规划文本，不像宣传稿或论文
6. 对不确定事项保持了证据边界和审慎表述
