# 指标体系与项目库设计

## 一、指标体系怎么设

先问四个问题：

1. 这个指标是否直接服务于规划目标？
2. 是否有稳定口径和可核实基期值？
3. 是否能通过规划期内的政策、项目或机制推动实现？
4. 是否与上位规划、统计制度、行业惯例大体一致？

如果四个问题里有两个答不上来，这个指标大概率不该进核心指标表。

## 二、指标分类建议

- `约束性指标`：底线管理、刚性要求、安全环保、资源约束、法定任务等
- `预期性指标`：发展质量、规模、效率、能力提升等
- `监测性指标`：需要持续观察但不宜写成刚性承诺的指标

常见组合：

- 结果类指标：反映最终成效
- 过程类指标：反映推进节奏
- 能力类指标：反映体系建设、平台建设、人才、数字化能力等
- 安全类指标：反映风险防控、绿色低碳、底线约束

## 三、核心指标表建议字段

至少保留以下字段：

| 字段 | 说明 |
|---|---|
| 指标名称 | 用官方或统计常用表述 |
| 指标属性 | 约束性 / 预期性 / 监测性 |
| 单位 | 与统计口径一致 |
| 基期值 | 基期年的已知数值 |
| 目标值 | 规划期末目标 |
| 口径说明 | 数据来源、统计范围、计算方法 |
| 牵头部门 | 负责监测和推动的单位 |

可选字段：

- 2027 年或中期节点值
- 上位规划对应指标
- 是否纳入年度计划

## 四、指标数量控制

- `specialized`：正文建议保留 `8-15` 个核心指标
- `regional`：正文建议保留 `10-18` 个核心指标
- 更多补充指标放附件，不要把正文写成统计年鉴

## 五、常见问题

- 只有目标值，没有基期值
- 指标单位前后不一致
- 同一指标在正文和附件用不同名称
- 目标值明显高于近年趋势且没有政策支撑
- 把“工作动作”误当成结果指标

## 六、项目库不是凑数

项目只有在能回答以下问题时才值得进入主项目库：

- 对应哪项重点任务？
- 为什么必须纳入本规划？
- 当前成熟度如何？
- 由谁牵头？
- 预计何时推进？
- 对什么指标或目标有直接贡献？

## 七、项目库建议字段

| 字段 | 说明 |
|---|---|
| 项目名称 | 尽量使用可识别的正式名称 |
| 项目类别 | 工程建设 / 平台建设 / 试点示范 / 改革事项等 |
| 对应任务 | 对应规划的哪项重点任务 |
| 主要内容 | 做什么，不超过 2-3 句话 |
| 成熟度 | 谋划 / 前期 / 在建 / 储备 |
| 实施时序 | 启动期 / 攻坚期 / 收官期，或具体年度 |
| 牵头主体 | 部门、园区、平台公司、事业单位等 |
| 预期成效 | 对指标、能力、服务、投资、协同的贡献 |
| 风险或边界 | 土地、资金、审批、数据待核等 |

## 八、项目分层

可以分三层：

- `重大工程`：必须体现规划导向和资源投向
- `重点项目`：直接支撑重点任务
- `储备项目`：方向明确但成熟度不足

不要把三层混成一个表。

## 九、实施矩阵建议字段

`14-implementation-matrix.md` 可至少包含：

| 重点任务 | 关键举措 | 牵头单位 | 配合单位 | 时间节点 | 对应指标/项目 | 评估方式 |
|---|---|---|---|---|---|---|

实施矩阵的价值在于：

- 让目标和任务可分解
- 让责任和协同关系可追踪
- 让中期评估和期末评估有抓手

## 十、写作时的保守规则

- 没有主管部门公开依据，不写精确投资额。
- 没有正式批复或权威公开信息，不把储备事项写成确定实施。
- 没有稳定口径，不用“翻番”“全国领先”这类高风险表达。
- 对跨区域项目和重大平台，优先写推进方向、合作机制和分工，不轻易写死投资收益数字。
