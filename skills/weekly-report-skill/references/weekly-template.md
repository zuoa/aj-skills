# 周报模板

按以下结构生成 Markdown；正文纵向罗列，不用表格。花括号是生成说明，最终报告中替换为实际内容。无事实支持的可选小节省略，未知事项只在“判断限制”概述范围。

```markdown
# 周报 — {起始日期} 至 {结束日期}

统计截止：{日期}；涉及部门：{部门列表}

## 一、本周摘要

{3–5 句话：本周关键结果、跟踪数量及分类、最大偏差、近期风险或需要决策的事。进行中不算达成；未知不算失败。}

## 二、本周目标与节点对照

### {目标名称}

目标与验收标准：{业务结果或指标目标、口径及统计周期}。
责任部门/负责人：{已确认信息}。
计划节点：{原始日期}；{有确认变更时写当前日期、变更原因}。
本周结果：{具体交付、本期新增和截至本期累计明确区分}。
完成状态：{已完成/进行中/未启动/暂停/取消}；时间状态：{提前/按期完成/延期/预计超期/尚未到期/无法判断}。
实际或预计完成：{日期及性质}；偏差：{可计算差额、延迟天数；无阶段基线时不评价进度落后}。
原因与影响：{已确认原因、受影响的节点或业务}。
后续动作：{纠偏动作、负责人、截止日期}。

{按事项重复。已完成但晚于承诺的目标仍需展示延期。未确认目标不得输出确定的达成结论。}

## 三、重点交付与计划外事项

{部门}：{本周重要结果及业务作用；目标对照已有的内容不重复铺陈}。
计划外事项：{新增工作、触发原因、对原计划的影响；没有则省略}。

## 四、阻碍、风险与需要支持的事项

{事项}：{已经发生的问题或未来风险；影响范围、处理动作、负责人、解除或复查日期}。
需要决策/协调：{请谁决定什么、最晚何时决定、对目标节点的影响；仅明确请求或标注建议}。

## 五、下周计划与近期节点

{目标关联}：{计划交付、验收标准、负责人、截止日期、依赖项}。
上期遗留：{本周仍未关闭、下周需跟进的动作与承诺}。

## 六、判断限制

{没有未知时写“本期目标与节点信息已完成核对。”；否则说明多少事项、哪些业务范围及哪些判断受影响，不列内部问题清单。}
{具体补充与确认过程见独立记录；不列材料来源。}
```
