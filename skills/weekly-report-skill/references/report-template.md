# 报告模板

以下是生成报告时应遵循的结构和格式。参考 `/Users/yujian/Documents/monthly/2026一季度总结及二季度规划.docx` 的纵向罗列结构，不使用表格。

---

# {周报 / 月报} — {时间范围}

生成时间：{时间}
涉及部门：{部门列表}
跟踪事项：{目标跟踪清单数量} 项

## 一、{本期周期}工作总结

### 1. 摘要

{3-5 句话。只写关键事实：本期跟踪事项数量、达成数量、偏差数量、资料缺口数量、主要风险。不做评价，不用形容词。}

示例：
本期共跟踪 X 项事项，X 项达成，X 项存在偏差，X 项资料缺口需补充确认。{最大偏差项}落后预期，原因为{文档中的原因；无记录则写"原因未说明"}。下期需关注{风险描述}。资料缺口已另列人工补充清单。

### 2. 规划里程碑完成情况及偏差

{按规划文件和上期总结文件中的事项逐条罗列。每条事项使用"事项：进展说明。"格式，不使用表格。无法形成进展判断的事项不要在本节逐条展开，全部写入人工补充清单。}

{事项名称}：{状态。实际进展。偏差/原因。}

状态写法：
- 已完成：用于完成或超额完成。
- 进度偏差：用于部分完成、有实质进展但未达预期。
- 未完成：用于明确未做、暂停、延期。
- 资料缺口：仅用于内部判断，不作为主报告状态输出；具体补充要求写入人工补充清单。

### 3. 指标

{按指标逐条罗列。每条指标使用"部门/指标：结果说明。"格式。能计算完成率则写完成率；无法计算则写"无法计算"。}

{部门或指标名称}：目标值{目标值；未说明写"未说明"}，本期结果{结果}，完成率/差额{完成率或差额；无法计算写"无法计算"}。

{缺少本期结果、统计口径或目标值的指标不要在主报告中输出占位句，写入人工补充清单。}

### 4. {专题/解决方案名称}

{如规划文件或本期总结中存在专题，例如校园解决方案、展会材料、重点产品方案，按专题单独成节。无专题时可省略本节。}

{专题名称}：{本期进展。输出物。偏差。材料不足以判断的专题不要输出占位句，写入人工补充清单。}

### 5. 各部门核心交付结果

{按部门逐条罗列。每个部门使用"部门：内容。"格式。必须覆盖规划文件和上期总结文件中出现的部门。}

{部门名称}：{完成事项。计划外事项可写"另新增{事项}"。存在问题写在同一段末尾或下一段。计划内但未说明进展的事项不要在此展开，写入人工补充清单。}

### 6. 存在的阻碍与风险

{按风险类别纵向罗列。风险来自本期偏差、部门问题、上期遗留风险、规划文件已识别风险。无进展说明的风险不要在主报告中输出占位句，具体问题写入人工补充清单。}

{风险类别}：
{风险事项}：{风险描述。影响。当前处理情况。}

## 二、{下期周期}工作规划

### 1. 核心里程碑

{按规划文件、上期总结文件和本期总结中明确提出的下期计划逐条罗列。}

（1）{里程碑事项}。{预期结果、时间节点、负责部门、依赖项或风险。}
（2）{里程碑事项}。{预期结果、时间节点、负责部门、依赖项或风险。}

### 2. 各部门核心交付计划

{按部门纵向罗列。月份计划可按"4月/5月/6月"或"第X周"继续缩进罗列。}

{部门名称}：
{时间节点}：{计划事项。预期结果。依赖项或风险。}
{时间节点}：{计划事项。预期结果。依赖项或风险。}
其他：{跨期支持事项、协同事项或待补充事项。}

{部门名称}：{计划事项。预期结果。依赖项或风险。}

### 3. 存在的风险

{只写会影响下期规划落地的风险。每条风险说明影响和需关注点，不标注来源。}

{风险事项}：{风险描述。影响{影响范围}。建议关注{关注点}。}

## 三、附注

资料缺口：
{写"另有 X 项事项需要补充确认，详见《{时间范围}-人工补充清单.md》"；如无写"无"。}

文件或资料异常：
{只写数量提示，例如"另有 X 个文件或资料异常已列入人工补充清单"；如无写"无"。不要在主报告列文件名。}

# 人工补充清单模板

以下内容单独保存为 `{时间范围}-人工补充清单.md`，不要混入主报告正文。清单用于补齐材料，不需要标注来源。

# {周报 / 月报}人工补充清单 — {时间范围}

生成时间：{时间}
待补充事项：{数量} 项
建议处理顺序：先补影响结论和风险判断的事项，再补普通进展描述。

## 一、里程碑和重点事项

{按事项逐条写。每条都要具体到可直接发给相关人员确认。}

所属板块：{里程碑 / 重点项目 / 专题}
涉及部门或责任人：{部门或责任人；无法判断写"待确认"}
当前缺口：{缺少完成状态 / 实际进展 / 输出物 / 偏差原因 / 时间节点 / 依赖项}
需要补充：
1. {需要确认的问题 1}
2. {需要确认的问题 2}
3. {需要确认的问题 3}
补充用途：{用于判断完成状态 / 偏差原因 / 下期风险 / 是否纳入下期计划}
建议优先级：{高 / 中 / 低}

## 二、指标数据

涉及部门或责任人：{部门或责任人；无法判断写"待确认"}

2. {统计口径、时间范围和单位是什么}
3. {与目标值的差额或未达原因是什么}
补充用途：{用于计算完成率、判断偏差或形成摘要数字}
建议优先级：{高 / 中 / 低}

## 三、部门材料

当前缺口：{本期总结缺失 / 计划内事项未说明 / 下期计划未说明 / 风险原因未说明}
需要补充：
1. {本期完成了哪些计划内事项}
2. {哪些事项延期、暂停或未启动，原因是什么}
3. {下期计划、时间节点和依赖项是什么}
补充用途：{用于部门核心交付结果、偏差分析或下期规划}
建议优先级：{高 / 中 / 低}

## 四、风险和阻碍

风险事项：{风险名称}
涉及部门或责任人：{部门或责任人；无法判断写"待确认"}
当前缺口：{缺少影响范围 / 处理进展 / 责任人 / 预计解除时间 / 是否影响下期计划}
需要补充：
1. {风险当前是否仍存在}
2. {已采取哪些处理动作}

4. {预计何时解除或需要哪些支持}
补充用途：{用于主报告风险段落和下期关注事项}
