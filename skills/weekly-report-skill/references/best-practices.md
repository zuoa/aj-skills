# 周期汇报实践依据

检索日期：2026-10-15。以下为方法参考，不能代替用户材料，也不意味着需要接入这些平台。

## 固定结构、决策导向

[Atlassian：Weekly Project Updates](https://www.atlassian.com/team-playbook/plays/weekly-project-updates) 建议异步周更新覆盖本周结果、需要帮助和下一步，并记录风险、决策理由及日期调整。用于本 skill：周报以变化和近期动作组织，重要问题写清谁需在何时做决定，不以部门活动堆叠充当结果。

[Atlassian：Project Status Report](https://www.atlassian.com/agile/project-management/status-report/) 将状态报告与目标、里程碑、进度和风险关联。用于本 skill：固定模板保留对照结构，每项结果能落到目标和时间节点；偏差说明影响及处理动作。

## 周检查和周期复盘不同

[What Matters：Why We Don't Grade OKRs Weekly](https://www.whatmatters.com/faqs/weekly-okr-grading-check-in) 区分周期内检查与周期末评价，强调提前识别阻碍、支持团队和调整行动。用于本 skill：周报关注是否需要纠偏；未到期的季度/年度目标不因周末尚未完成而判失败；月报也只评价本月承诺和真正已到期目标。

## 目标关联与历史快照

[Asana：Project Progress and Status Updates](https://help.asana.com/s/article/project-progress-and-status-updates?language=en_US) 将状态更新与目标、里程碑和关键资源关联，支持固定内容块及状态快照。用于本 skill：持续保存稳定目标 ID、原始承诺、变更记录和本期事实快照，后续对照历史，不从润色后的报告重新猜测事实。

## 本 skill 的实现选择

逐项缺口表单、明确未知、阻止未提交生成、本地标准库服务、台账文件锁及口径校验，是针对用户要求作出的实现设计，并非以上来源统一规定。目标是让用户补充可回答的业务事实，并让报告完整覆盖已承诺事项。
