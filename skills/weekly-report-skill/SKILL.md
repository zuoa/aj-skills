# 周报 / 月报生成 Skill

## 定位

- **输入**：本期各部门总结文件夹 + 规划文件（Markdown / DOCX / TXT）+ 上期总结文件（Markdown / DOCX / TXT，可多份）
- **输出**：一份给老板和经营团队的整体汇报报告
- **风格原则**：客观、简洁、诚实。数据说话；无数据则如实写"无记录"；禁用模糊词
- **核心原则**：规划文件和上期总结文件共同构成完整跟踪台账。即使本期输入文件没有说明某项目标、计划或指标的进展，也必须在对应章节中保留该条目，标注"无记录，待人工补充"。

---

## 第一步：理解输入

### 1.1 获取输入文件

询问用户（如果未提供）：
- 部门文档所在文件夹路径
- 规划文件路径
- 上期总结文件路径（用于提取上期遗留事项、上期风险、上期下期计划；可提供多份）
- 报告周期（本周 / 本月 / 自定义日期范围）

如用户未提供规划文件或上期总结文件，先补问，不要直接生成报告。

### 1.2 遍历文件夹

```bash
find <folder_path> -type f | sort
```

按以下优先级处理文件：

| 优先级 | 文件类型 | 处理方式 |
|--------|----------|----------|
| 高 | `.md` `.txt` | 直接读取 |
| 高 | `.docx` | 用 docx skill 读取 |
| 中 | `.pdf` | 用 pdf-reading skill 读取 |
| 低 | `.xlsx` `.csv` | 提取关键数字/表格 |
| 跳过 | 图片、压缩包等 | 在报告中标注"存在但未解析" |

读取每个文件后，记录：
- 文件名（作为来源标识）
- 所属部门（从文件名或路径推断）
- 文件修改时间（用于判断是否在报告周期内）

⚠️ 如果文件修改时间明显早于报告周期，在报告中标注"时间存疑"。

### 1.3 读取规划文件

解析规划文件，提取：
- 每条里程碑、指标、重点项目、部门计划和风险事项
- 每条目标的**可量化指标**（如有）
- 目标负责部门/负责人
- 预期完成时间节点

规划文件可以是季度/月度规划，也可以是年度规划、阶段规划或上一期总结中的下一期规划。读取时按以下层级建立"目标跟踪清单"：

1. **规划里程碑**：例如产品发布、试点落地、平台交付、验收节点。
2. **指标**：例如外部验收金额、内部验收金额、收入目标、完成率。
3. **专题/解决方案**：例如校园解决方案、展会材料、重点方案更新。
4. **各部门核心交付计划**：按部门拆分，不合并成笼统表述。
5. **已识别风险/阻碍**：作为下期风险跟踪项保留。

参考输出形态：
- 先写"规划里程碑完成情况及偏差"，逐条对照目标与实际。
- 再写"指标"和"各部门核心交付结果"。
- 最后写"存在的阻碍与风险"和"下期规划"。
- 不要只输出本期文件里提到的事项；目标清单中的未提及事项也要出现，供人工补充。

### 1.4 读取上期总结文件

解析上期总结文件，提取：
- 上期未完成事项、偏差事项、无记录事项
- 上期风险与阻碍
- 上期报告中的"下期计划"或后续待办
- 上期已承诺的时间节点、指标目标、负责部门

将这些内容并入目标跟踪清单，类别标记为"上期遗留"或"上期计划"。如果某事项同时存在于规划文件和上期总结文件中，以规划文件为主，补充上期总结中的进展背景、风险原因或历史状态。

---

## 第二步：信息提取与分类

对每个部门文档，提取以下信息（能提取到多少就写多少，提取不到的不要推断）：

**本期完成事项**
- 具体做了什么，结果是什么（有数字则保留数字）

**目标关联情况**
- 对应规划文件或上期总结文件中的哪条目标/计划/遗留事项
- 完成程度：完成 / 部分完成 / 未完成 / 未提及

**计划外事项**
- 规划文件和上期总结文件中没有、但实际做了的事

**下期计划**
- 文档中明确提到的下期计划或待办

**风险与阻碍**
- 文档中提到的问题、延误原因、依赖未到位等

---

## 第三步：偏差分析

对照目标跟踪清单，逐条分析：

```
目标 → 实际 → 偏差类型 → 原因（如有记录）
```

偏差类型分三类：
- ✅ **达成**：按期或超额完成
- ⚠️ **偏差**：部分完成，有明确进展
- ❌ **未完成**：无记录 或 明确说明未做

**重要规则：**
- 偏差清单必须覆盖目标跟踪清单中的所有条目，不能因为本期总结没有进展说明而省略。
- 如果某目标或上期遗留事项在所有部门文档中均无相关记录，在对应事项后写：`无记录，待人工补充`；来源写：`规划文件/上期总结文件；本期总结无记录`。
- 如果规划文件或上期总结文件中列出部门计划，但部门总结未覆盖，仍要在对应部门小节的计划内事项中列出。
- 不要根据"常识"或"推断"填补空白
- 原因栏只写文档中明确提到的内容，否则留空

---

## 第四步：生成报告

按以下结构输出，见 `references/report-template.md`。

关键格式要求：
- 摘要不超过 5 句话
- 每个结论后标注来源文件（括号内）
- 偏差清单是核心，必须完整覆盖目标跟踪清单
- 报告正文参考 `references/report-template.md`，采用纵向罗列结构，不使用表格
- 规划文件或上期总结文件中有要求、但本期输入无进展说明的事项，不单独汇总成"待人工补充项"章节，而是放回其所属的里程碑、指标、部门工作、风险提示等对应内容中标注
- 禁止使用的词：基本完成、大体上、整体良好、稳步推进、有序开展

---

## 注意事项

**处理多文件同一部门**：同一部门有多个文件时，合并内容，标注所有来源文件。

**处理文件读取失败**：在报告"附注"中列出无法读取的文件，不要跳过不提。

**处理规划文件或上期总结文件格式不规范**：如结构不清晰，先列出你解析出的目标跟踪清单，让用户确认后再继续。

**报告语气**：陈述事实，不做评价。不写"表现优秀"、"值得表扬"之类的定性描述，除非用户明确要求。
