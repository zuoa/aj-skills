# 周报 / 月报生成 Skill

## 定位

- **输入**：本期各部门总结文件夹 + 规划文件（Markdown / DOCX / TXT）+ 上期总结文件（Markdown / DOCX / TXT，可多份）
- **输出**：两份文件：一份给老板和经营团队的整体汇报报告；一份单独的人工补充清单
- **风格原则**：客观、简洁、诚实。数据说话；无数据则不推断，缺口进入人工补充清单；禁用模糊词
- **核心原则**：规划文件和上期总结文件共同构成完整跟踪台账。主报告只写可直接汇报的事实和结论，不标注来源，不在正文中夹杂人工补充明细；需要人工补充或确认的内容必须单独生成补充清单，并写清需要补什么、向谁确认、为什么需要补。

---

## 第一步：理解输入

### 1.1 获取输入文件

先识别用户是否给出了报告周期，例如：
- `202605`
- `2026-05`
- `2026年5月`
- `5月周报`、`5月月报`

如果用户未提供部门文档所在文件夹路径，但提供了报告周期，先在当前运行目录下自动扫描匹配目录，不要直接询问用户。扫描优先级如下：

1. 精确匹配周期目录：例如用户要生成 `202605`，优先查找当前运行目录下的 `202605/`。
2. 规范化匹配：将 `2026-05`、`2026年5月`、`2026年05月` 统一尝试匹配 `202605/`、`2026-05/`、`2026年05月/`、`2026年5月/`。
3. 包含匹配：如果没有精确目录，查找当前运行目录下一层中名称包含该周期的目录，例如 `202605月报材料/`、`2026-05部门总结/`。

推荐扫描命令：

```bash
find . -maxdepth 2 -type d | sort
```

目录选择规则：
- 只有一个明显匹配目录时，直接把它作为部门文档所在文件夹。
- 有多个匹配目录时，列出候选目录并让用户选择。
- 没有匹配目录时，再询问用户提供部门文档所在文件夹路径。
- 规划文件和上期总结文件如果也未提供，可在匹配目录内优先查找名称包含 `规划`、`计划`、`上期`、`总结`、`复盘` 的文件；仍无法判断时再补问。

询问用户（仅在自动扫描无法确认时）：
- 部门文档所在文件夹路径
- 规划文件路径
- 上期总结文件路径（用于提取上期遗留事项、上期风险、上期下期计划；可提供多份）
- 报告周期（本周 / 本月 / 自定义日期范围）

如自动扫描后仍无法确认规划文件或上期总结文件，先补问，不要直接生成报告。

### 1.2 遍历文件夹

```bash
find <folder_path> -type f | sort
```

按以下优先级处理文件：

| 优先级 | 文件类型 | 处理方式 |
|--------|----------|----------|
| 高 | `.md` `.txt` | 直接读取 |
| 高 | `.docx` | 用 docx skill 读取 |
| 中 | `.pdf` | 用 pdf-reading skill 读取 |
| 低 | `.xlsx` `.csv` | 提取关键数字/表格 |
| 跳过 | 图片、压缩包等 | 记录到人工补充清单的"文件或资料异常" |

读取每个文件后，记录：
- 文件名（仅作内部核对，不写入主报告正文）
- 所属部门（从文件名或路径推断）
- 文件修改时间（用于判断是否在报告周期内）

⚠️ 如果文件修改时间明显早于报告周期，记录到人工补充清单的"文件或资料异常"中。

### 1.3 读取规划文件

解析规划文件，提取：
- 每条里程碑、指标、重点项目、部门计划和风险事项
- 每条目标的**可量化指标**（如有）
- 目标负责部门/负责人
- 预期完成时间节点

规划文件可以是季度/月度规划，也可以是年度规划、阶段规划或上一期总结中的下一期规划。读取时按以下层级建立"目标跟踪清单"：

1. **规划里程碑**：例如产品发布、试点落地、平台交付、验收节点。
2. **指标**：例如外部验收金额、内部验收金额、收入目标、完成率。
3. **专题/解决方案**：例如校园解决方案、展会材料、重点方案更新。
4. **各部门核心交付计划**：按部门拆分，不合并成笼统表述。
5. **已识别风险/阻碍**：作为下期风险跟踪项保留。

参考输出形态：
- 先写"规划里程碑完成情况及偏差"，逐条对照目标与实际。
- 再写"指标"和"各部门核心交付结果"。
- 最后写"存在的阻碍与风险"和"下期规划"。
- 不要只分析本期文件里提到的事项；目标清单中的未提及事项也要纳入内部核对，无法形成主报告结论的，进入人工补充清单。

### 1.4 读取上期总结文件

解析上期总结文件，提取：
- 上期未完成事项、偏差事项、无记录事项
- 上期风险与阻碍
- 上期报告中的"下期计划"或后续待办
- 上期已承诺的时间节点、指标目标、负责部门

将这些内容并入目标跟踪清单，类别标记为"上期遗留"或"上期计划"。如果某事项同时存在于规划文件和上期总结文件中，以规划文件为主，补充上期总结中的进展背景、风险原因或历史状态。

---

## 第二步：信息提取与分类

对每个部门文档，提取以下信息（能提取到多少就写多少，提取不到的不要推断）：

**本期完成事项**
- 具体做了什么，结果是什么（有数字则保留数字）

**目标关联情况**
- 对应规划文件或上期总结文件中的哪条目标/计划/遗留事项
- 完成程度：完成 / 部分完成 / 未完成 / 未提及

**计划外事项**
- 规划文件和上期总结文件中没有、但实际做了的事

**下期计划**
- 文档中明确提到的下期计划或待办

**风险与阻碍**
- 文档中提到的问题、延误原因、依赖未到位等

---

## 第三步：偏差分析

对照目标跟踪清单，逐条分析：

```
目标 → 实际 → 偏差类型 → 原因（如有记录）
```

偏差类型分四类：
- ✅ **达成**：按期或超额完成
- ⚠️ **偏差**：部分完成，有明确进展
- ❌ **未完成**：明确说明未做、暂停、延期
- 📝 **资料缺口**：无记录或无法判断；不进入主报告正文，写入人工补充清单

**重要规则：**
- 偏差分析必须覆盖目标跟踪清单中的所有条目，不能因为本期总结没有进展说明而省略内部核对。
- 如果某目标或上期遗留事项在所有部门文档中均无相关记录，不要把"无记录，待人工补充"写进主报告正文；将该事项写入单独的人工补充清单。
- 如果规划文件或上期总结文件中列出部门计划，但部门总结未覆盖，不要在主报告部门小节硬写缺口明细；将该缺口写入人工补充清单，并细化需补的进展、指标、原因、时间节点或负责人。
- 不要根据"常识"或"推断"填补空白
- 原因栏只写文档中明确提到的内容，否则留空

---

## 第四步：生成输出文件

按以下结构输出两份文件，见 `references/report-template.md`。

关键格式要求：
- 摘要不超过 5 句话
- 主报告正文不标注来源文件，不写"来源："，不写文件路径，不在句末加括号来源
- 主报告开头不列"本期来源文件""规划文件""上期总结文件"等来源信息
- 主报告不设置"待人工补充项"章节；补充事项只出现在人工补充清单文件中
- 偏差分析是核心，主报告与人工补充清单合计必须完整覆盖目标跟踪清单
- 报告正文参考 `references/report-template.md`，采用纵向罗列结构，不使用表格
- 规划文件或上期总结文件中有要求、但本期输入无进展说明的事项，统一写入人工补充清单，并按所属板块细化
- 禁止使用的词：基本完成、大体上、整体良好、稳步推进、有序开展

### 4.1 主报告文件

建议文件名：`{报告周期}-整体汇报报告.md`。

主报告用于直接汇报，要求：
- 不标注来源，不出现文件名式引注
- 不暴露内部核对过程
- 不把缺口明细写进正文
- 对缺口只在摘要或附注中保留总量级提示，例如"另有 X 项资料缺口已列入人工补充清单"
- 只写已有材料能够支撑的进展、偏差、风险和下期计划

### 4.2 人工补充清单文件

建议文件名：`{报告周期}-人工补充清单.md`。

人工补充清单用于让相关人员补齐材料，要求每条缺口至少写清：
- 所属板块：里程碑 / 指标 / 专题 / 部门交付 / 风险 / 下期计划 / 文件或资料异常
- 事项名称
- 涉及部门或责任人（材料中无法判断时写"待确认"）
- 当前缺口：缺少进展、结果数字、完成状态、偏差原因、时间节点、负责人、风险处理情况等
- 需要补充的具体内容：拆成可回答的问题，不要只写"请补充"
- 补充后的用途：会用于主报告的哪个判断，例如完成状态、偏差原因、下期风险、指标完成率
- 建议优先级：高 / 中 / 低；影响主报告结论或老板决策的问题标为高

人工补充清单也不需要做来源标注；只保留业务事项、部门、缺口和待确认问题。

---

## 注意事项

**处理多文件同一部门**：同一部门有多个文件时，合并内容；来源信息只作内部核对，不写入主报告。

**处理文件读取失败**：在人工补充清单的"文件或资料异常"中列出无法读取的文件和跳过原因，不要写进主报告正文。

**处理规划文件或上期总结文件格式不规范**：如结构不清晰，先列出你解析出的目标跟踪清单，让用户确认后再继续。

**报告语气**：陈述事实，不做评价。不写"表现优秀"、"值得表扬"之类的定性描述，除非用户明确要求。
