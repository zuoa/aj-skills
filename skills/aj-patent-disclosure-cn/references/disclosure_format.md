# 按用户提供的技术交底书模板成稿

## 唯一默认模板

使用资源目录中的 [技术交底书模板.docx](../assets/templates/技术交底书模板.docx)。这是用户指定的交付格式，优先于先前整理的通用章节及 `cnipa-reference.docx`。原文件作为基线保存，不修改、不用示例内容覆盖实际发明。公开写作规范仍用于检查充分公开，不能据此换掉本模板的结构。

## 结构及字段映射

首页沿用原模板五行双列表格及合并单元格：发明名称、发明人姓名、所属部门、第一发明人身份证号。分别取 `title`、`inventors`、`department`、`first_inventor_id`。仅使用用户提供的个人信息；姓名、部门或身份证号缺失时相应值为空，不填星号、猜测值或“待确认”。这类行政字段缺失不影响技术正文导出，不为了补身份证号扫描无关文件。

正文保持模板五个问答式章节，顺序不变：

1. **本发明的关键点和欲保护点是什么？** 先提炼 `protection_points`（或 `invention.key_features`），再用内部小节展开技术领域、术语、背景技术、技术问题、发明目的、完整技术方案和具体实施方式。模板没有独立设置这些技术章节，不应因此丢弃充分公开所必需的内容。
2. **与现有技术相比，本发明有何优点？** 对应 `invention.effects`，逐项说明手段与效果的因果关系及对比依据。模板原文“与第2条所属的最好的现有技术相比”在提供文件中没有正确的对应条目，成稿改为本标题并明确具体比较对象。
3. **本发明是否经过实验、模拟、使用而证明可行，结果如何？** 对应 `verification`，说明真实验证状态、方法、条件、基线、结果及依据。已明确尚未进行实验时如实描述，并区分机理说明与实验结果；没有验证信息时在定稿前补齐，绝不能沿用模板“已经通过实验、研制出样机”的示例结论。
4. **本发明的变更设计（替代方案）及其它用途：** 对应 `invention.alternatives`、`alternative_statement`、`other_uses`。说明可替换步骤/组件、条件、效果取舍及适用范围。无替代方案时依据已知事实写明，不默认把未知当作“无”。
5. **附图及说明** 对应 `figures`，嵌入所有实际图像，逐图列图号、图名及主要标记说明；流程、分支和步骤与第一节对应。

第一章内依次单列“要解决的技术问题”“发明目的”“技术方案”。`invention.technical_problem` 描述现有技术的具体不足；`invention.purpose` 描述针对该不足要达到的技术目标；两者独立输出，不互相替代。发明目的不能把尚未验证的效果写成已实现结果。草稿缺少 purpose 时报告警告，起草依据确认与终稿导出前必须补齐，旧输入不会自动猜写目的。

参考资料在背景或技术方案内就近引用，不再增设通用模板的独立尾章。不要添加独立封面、摘要草案、内部附录、假设清单、待确认项或下一步建议。

## 保留版式与清理示例

复制原始首页表格（含合并、边框和单元格格式）及节设置：A4，上下页边距 1440 twips（2.54 cm），左右 1800 twips（3.175 cm），原有页眉/页脚距离与文档网格保留。正文保持模板的 10.5 pt 宋体和 1.2 倍行距；标题采用微软雅黑并显式加粗：五个主章 14 pt、主题小节 12 pt、步骤及细分小标题 11 pt，段前/段后分别为 12/6、10/5、7/4 pt。标题与下段同页、标题自身不跨页，取消模板直接格式对字号与加粗的覆盖。输入、处理、输出、验证方法等段内标签加粗；保留问答的真实 Word 编号。填写内容使用黑色，模板的灰色机器人例文和蓝色/楷体填写说明不带入终稿。

原模板含机器人例文、“XX”替代占位、星号、撰写指导及注意事项。这些用于理解写法，不属于新发明。严禁原样保留或改几个名词充当实际方案。

`generate_docx.py` 默认引用原模板，并在导出时复制首页表格及版式、填入字段、嵌图。Markdown 保持相同问答顺序和元数据；因 Markdown 不支持合并单元格，首页表格采用等价的字段—值表示。

## 终稿覆盖检查

完整导出自动执行 `check_output_coverage.py`：先检查 Markdown，再检查真实 DOCX。五个主章及关键小节必须齐全且顺序正确，必需内容不得为空；逐项核对已提供的技术问题、发明目的、关键特征、步骤、实施例、效果、验证情况、替代方案和附图说明是否保留在对应主章及关键小节。可选内容未提供时标为不适用，已提供则同样检查，不能静默丢弃。

默认生成同名 `.quality.json`，包含覆盖矩阵、错误、警告和文件哈希。失败时命令返回非零，不能提交为最终交付；导出后检查失败时保存 `.failed-quality.json`，已生成文件仅供排错。交付阶段要求覆盖检查通过。文本覆盖与字段检查不证明科学充分性或真实性；语义一致性和页面视觉仍需审阅。

独立复查已有产物：

```bash
python3 scripts/check_output_coverage.py --input <交底输入.json> \
  --markdown <交底书.md> --docx <交底书.docx> --report <覆盖报告.json>
```

旧输入如果缺少步骤输入/触发条件、输出/状态变化、实施例结果或保护点，须先据实补齐。不得为通过校验自动编造。正文覆盖范围内的额外嵌套字段如果未被渲染，会报告遗漏；应归入适当的正式字段或明确保留在内部记录。内部事实表、检索记录、假设状态及任意自定义顶层字段不自动视为正式正文；需要进入正文的内容应放到相应正式字段。检查也拒绝只有标点的必需章节、正文放错关键小节、Markdown 只留图题及 Word 重复图片替代漏图的情况。
