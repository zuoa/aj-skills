# 现有技术检索与证据规则

## 目标

检索的目的不是寻找几个“看起来相似”的摘要，而是建立可复核的证据链：哪些技术特征被何时、由哪一份文献公开，哪些区别特征组合可能构成创新点，现有技术是否给出采用这些区别特征的技术启示，以及检索仍有哪些盲区。

## 一、检索前提

先记录：

- 拟申请日、优先权日或用户指定的检索截止日；
- 发明的一句话技术构思；
- 独立主题候选及其必要技术特征；
- 同义词、上位词、下位词、缩写、中英文术语；
- 可能的 IPC/CPC 入口（仅作检索线索，使用时核验当前分类版本）。

不要把“最近 10 年”设为唯一范围。新颖性相关现有技术可能更早；时间过滤只用于提高效率，不能替代完整性判断。

## 二、检索顺序

### 1. 概念宽检

分别组合：

- 技术问题 + 处理对象；
- 核心手段 + 关键关系；
- 输入/输出 + 效果指标；
- 核心模块/步骤的同义表达；
- 英文术语、缩写和常见翻译。

避免用整段发明描述直接搜索，因为措辞变化会造成漏检。

### 2. 分类与主体精筛

- 从高相关文献提取 IPC/CPC，再交叉检索关键词；
- 检索主要申请人、发明人、同族和引证/被引证文献；
- 对中国申请核对 CNIPA 公开文本；外国专利核对相应官方数据库或 WIPO/EPO 文本；
- 必要时检索论文、标准、产品手册、开源代码、会议材料等非专利文献。

### 3. 逐项阅读

对高相关文献至少核对：

- 标题、公开号/文献标识、公开日、优先权日；
- 申请人/作者；
- 独立权利要求；
- 说明书中真正公开相关关系的段落和附图；
- 同族中是否存在更早公开文本；
- 文献是否在检索截止日前已向公众公开。

摘要只能用于筛选，不能单独支撑复杂的特征判断。

## 三、创新点发现闭环

### 1. 建立检索基线

先把每个待检索候选拆成特征编号：

| 编号 | 必要技术特征 | 功能/关系 | 预期效果 | 事实状态 | 正文依据 |
|---|---|---|---|---|---|
| F1 |  |  |  | 用户已确认/资料有据/待确认 |  |

第一轮检索寻找整体方案和各核心子机制的最接近现有技术，不要只搜索完整句子，也不要只找标题相似的专利。

### 2. 提取区别特征

将本方案与每份高相关单一文献逐项对照，标出：

- 已明确公开的特征；
- 可能隐含但需要论证的特征；
- 未见公开的区别特征；
- 文献采用了不同手段但解决相同问题的部分。

区别特征只是创新点的原料，不是结论。应用场景、数据名称、业务目标、颜色布局、孤立参数变化或常规模块并列，通常不能仅因“文献没写同样的词”就列为创新点。

### 3. 对区别特征做反向检索

对每组区别特征至少组合以下维度再次检索：

- 区别特征的同义词、上位概念和技术动作；
- 区别特征与前后步骤/模块的功能关系；
- 区别特征解决的实际技术问题；
- 区别特征产生的技术效果或评价指标；
- 高相关 IPC/CPC、同族、引证和被引证文献。

反向检索的目的，是主动寻找能够否定或削弱候选的文献。若单一文献已经公开全部必要特征，应淘汰或重构候选；若其他文献给出明确组合启示，应提高创造性风险；若存在适配障碍、反向教导、协同作用或预料不到的效果，应记录证据位置。

### 4. 形成创新点候选

使用下表输出，而不是只列“创新点名称”：

| 候选 | 最接近现有技术 | 区别特征组合 | 作用机理与技术效果 | 方案支撑 | 反向检索结果 | 风险/置信度 | 建议定位 |
|---|---|---|---|---|---|---|---|
| P1 |  |  |  |  |  |  | 核心/从属/淘汰/研发建议 |

“初步创新点候选”至少应具备：有事实支撑的特征组合、相对最接近现有技术的可定位区别、特征与效果之间的因果关系，以及没有被反向检索立即推翻的证据状态。它仍是检索范围内的初步判断，不等于法定新颖性、创造性结论或授权保证。

### 5. 迭代收敛

把首轮结果分为：

1. 核心候选：继续作为独立主题研究；
2. 从属候选：单独贡献有限，但适合作为进一步限定；
3. 高风险候选：与现有技术接近，需要效果证据或更具体关系；
4. 淘汰项：已被单一文献公开，或仅是非技术差异；
5. 研发建议：现有材料未实现，不得写成既有发明。

收缩或重组候选后，再检索新的特征组合。若没有留下强候选，如实给出“当前材料暂未识别出证据充分的核心创新点”，并列出需要补充的技术机制、实验或研发方向。

## 四、检索记录格式

每份文献记录：

| 字段 | 要求 |
|---|---|
| 文献标识 | 公开号、DOI、标准号或稳定标识 |
| 标题 | 与公开文本一致 |
| 公开日/优先权日 | 分开记录，不混用 |
| 申请人/作者 | 与来源一致 |
| 来源链接 | 直接指向公开文本或官方记录 |
| 相关位置 | 权利要求号、段落号、页码或图号 |
| 公开内容 | 客观摘述，不扩大解释 |
| 与本方案关系 | 相同、部分相同、背景相关或仅关键词相似 |
| 核验状态 | 已核验全文/仅核验摘要/待核验 |

无法核验的字段写“待核验”，不得补造。

## 五、新颖性特征对照

对每个独立主题制作单一文献对照表：

| 必要技术特征 | 对比文件 1 | 证据位置 | 结论 |
|---|---|---|---|
| F1 | 明确公开 | 权利要求 1 | 是 |
| F2 | 未见公开 | — | 否 |
| F3 | 仅可能隐含 | 段落 [0032] | 需论证 |

判断纪律：

- 新颖性以一份对比文件是否直接、明确公开全部必要技术特征为核心；
- 不把多份文献拼接后称为“不新颖”；
- 文字相似度不是法律判断；
- “可能隐含”需要说明为何本领域技术人员能直接、无歧义地得出；
- 输出“初步检索未发现”而不是“全球首次”或“绝对新颖”。

## 六、创造性分析

按以下链条写，避免直接给主观分数：

1. 选择最接近现有技术，并说明选择理由；
2. 逐项确定区别特征；
3. 根据区别特征产生的技术效果，重述实际解决的技术问题；
4. 查找现有技术整体是否给出采用该区别特征的技术启示；
5. 评估结合动机、适配难点、相互作用、预料不到的效果和反向教导；
6. 给出“风险高/中/低 + 证据置信度”，并说明检索局限。

AI/算法方案特别检查：

- 仅应用对象或行业场景不同，算法流程和模型参数没有实质变化；
- 相同场景下是否针对数据特性调整特征、结构、层级、损失函数或训练策略；
- 算法特征是否与技术特征功能上相互支持并产生技术效果；
- 申请材料是否充分披露这些调整，而不只是事后论证。

## 七、风险措辞

推荐：

- “在已检索数据库和检索式范围内，尚未发现单一文献同时公开 F1–F5。”
- “文件 X 公开 F1–F3；F4 的差异能否产生非显而易见的技术效果，取决于待补实验。”
- “当前结论置信度为中，原因是未完成非专利文献和英文同义词检索。”

避免：

- “相似度 82%，所以不新颖”；
- “授权概率 90%”；
- “没有任何相关专利”；
- 没有实际检索却列出公开号或申请人；
- 把优先权日误写成公开日；
- 只读摘要便断言文献公开了全部技术关系。
