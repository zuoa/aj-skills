# 非破坏性修订、版本留痕与脱敏

## 目标

在已有交底书上补材料、纠错或调整保护重点时，保留旧稿、来源和决策链，并把修改传播到所有受影响章节。脱敏只移除不必要的身份和商业信息，不能损坏技术可实施性。

## 一、识别修订模式

| 类型 | 典型意图 | 处理 |
|---|---|---|
| 补充 | 新增代码、测试、实施方式或附图 | 合并新证据，检查是否改变技术实质 |
| 纠错 | 参数、流程、事实或术语不正确 | 以确认后的事实为准，传播修正 |
| 策略调整 | 强调另一保护主线、拆分主题 | 重做必要特征和支撑矩阵，必要时补检索 |
| 纯格式 | 名称、版式、措辞或文件格式 | 不重跑无关的挖掘和检索 |

已有稿修订默认进入本流程，不要无故从头重写。只有用户明确要求重构，或增量改变了发明构思，才回到专利点挖掘。

## 二、建立修订基线

记录：

- 基线文件路径、版本名和 SHA-256；
- 本轮用户说明与新增材料；
- 本轮修订类型；
- 检索截止日与检索结论版本；
- 拟保留、不修改和禁止覆盖的范围。

默认另存：

```text
交底书_[规范化发明名称]_v<版本>_<YYYYMMDDHHMMSS>.md
交底书_[规范化发明名称]_v<版本>_<YYYYMMDDHHMMSS>.docx
```

若项目已有自己的版本规则，沿用项目规则。除非用户明确要求，不覆盖旧稿。

## 三、修改影响传播

任何事实或策略变化都检查以下链路：

```text
事实/证据
  → 技术问题
  → 必要技术特征与步骤/模块
  → 技术效果
  → 发明内容
  → 实施例
  → 拟保护主题与支撑矩阵
  → 附图与标记
  → 检索对比与风险结论
```

常见联动：

- 改参数：同步公式、参数表、实施例、效果条件；
- 改模块关系：同步系统方案、方法步骤、附图和支撑矩阵；
- 改核心区别特征：重新检查检索式、单文献对照和创造性分析；
- 删除事实：检查是否仍有必要特征或效果依赖它；
- 新增替代实现：确认是已实现事实、合理推断还是研发建议。

只修改目标章节但留下全文矛盾，视为修订未完成。

## 四、冲突与纠错

当新材料推翻旧稿时：

1. 标明旧说法、来源和受影响位置；
2. 标明新说法、来源和确认状态；
3. 说明为什么采用新说法；
4. 删除或改写所有依赖旧说法的结论；
5. 不在正文保留互相矛盾的“两种可能”来逃避判断；确实未确认时移入待确认项。

## 五、脱敏分层

先建立内部脱敏映射，映射表不进入对外交底书：

| 原始信息 | 对外表述 | 是否影响技术实施 | 处理理由 |
|---|---|---:|---|
| 客户/产品名称 | 客户端/目标系统 | 否 | 身份信息无关 |
| 内部服务名 | 功能模块名 | 否 | 保留技术职责 |
| 精确业务规模 | 经确认的范围或条件 | 可能 | 防止丢失参数依据 |

分层原则：

- **应去除**：客户、公司、内部代号、账号、密钥、真实个人信息和不必要的业务标签；
- **可抽象**：产品名、服务名、业务实体名，但保留模块职责与交互关系；
- **谨慎抽象**：数据字段、阈值、范围、时序、协议和部署约束；
- **不得删除**：支撑必要特征、可实施性或技术效果的关键细节。

不能用“预设”“适当”“智能”“一定规模”掩盖必须披露的技术条件。若数值确属商业秘密，应与用户讨论是否用有依据的范围、判定规则或替代参数表达，而不是直接删空。

## 六、修订记录

交付后运行：

```bash
python3 scripts/revision_log.py \
  --case-dir <案件目录> \
  --kind supplement \
  --base <上一版文件> \
  --artifact <本轮.md> \
  --artifact <本轮.docx> \
  --changed-section "发明内容" \
  --changed-section "实施例1" \
  --summary "补充异常回退路径，并同步附图和支撑矩阵" \
  --search-impact "核心区别未变，无需补检索" \
  --claim-impact "从属限定新增回退条件" \
  --figure-impact "图2新增回退分支" \
  --redaction-impact "内部服务名已抽象为功能模块名"
```

脚本会追加 `revision_history.md` 和 `revision_history.jsonl`，记录本地时间、UTC、基线和交付物哈希；不会覆盖既有记录。

## 七、交付摘要

对话中简要说明：

- 新版本路径；
- 改了哪些章节，依据是什么；
- 是否影响核心保护点和检索结论；
- 是否同步了实施例、附图和支撑矩阵；
- 仍待确认的事项；
- 旧稿已保留。
